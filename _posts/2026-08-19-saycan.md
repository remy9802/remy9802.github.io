## 核心结论

SayCan 的关键不是让 LLM 直接输出连续机器人动作，而是让它只在一个**已知技能库**中评分：语言模型提供“该技能能否推进指令”的先验，机器人价值函数提供“当前状态下能否成功”的可供性分数，两者相乘后选择下一项技能。这个非常简洁的因子分解把开放语言理解与封闭机器人能力接在了一起。

在作者的 101 条指令评测中，SayCan 在 mock kitchen 达到 **84% 规划成功率、74% 执行成功率**，在真实办公厨房达到 **81% 与 60%**；去掉价值函数的 `No VF` 只有 67% 的 mock-kitchen 规划成功率。它支持的强结论是：在既定对象、环境和技能集合内，可供性分数能过滤很多“语言合理但机器人做不到”的候选动作，并让多个已训练技能组合成长时程任务。

但 SayCan 不是通用开放世界规划器。系统最多只能调用 551 个预先训练并命名的技能；低层技能失败仍是主要执行瓶颈；LLM 在执行中看不到连续视觉状态，也不会自动从失败轨迹学习。论文所谓“zero-shot”是**高层技能组合的零样本泛化**，不是机器人动作技能的零样本获得。

## 研究背景

大语言模型能从互联网文本中吸收常识，因而常能回答“把苹果放到桌上需要哪些步骤”。问题是语言概率并不等于物理可执行性：LLM 可能建议拿起当前不存在的苹果、调用机器人没有的能力，或在物体太远时直接抓取。另一方面，机器人强化学习或行为克隆得到的价值函数很会判断某个短技能能否在当前观测下成功，却不理解一个新自然语言目标需要怎样的技能序列。

SayCan 将这两个模型各自限制在擅长的部分：

- LLM 负责语义先验和长程组合；
- 已训练技能及其价值函数负责具身约束；
- 规划器只做逐步重评分，不重新训练 LLM 或低层策略。

它处在后来“LLM 具身智能体”路线的起点：与直接生成 Python 的 Code as Policies 不同，SayCan 只从受控技能菜单中选择；与 Inner Monologue 不同，它原始版本只有间接的技能终止反馈，没有把检测到的世界状态持续写回语言上下文。

## 研究问题

1. LLM 的语言相关性与价值函数的状态可执行性，能否作为两个互补因子组合？
2. 这种逐步技能选择能否处理训练时未出现过的自然语言指令与更长技能链？
3. 价值函数是否真的比纯 LLM、生成式投影或语言条件策略更能约束规划？
4. 系统从 mock kitchen 迁移到真实办公厨房时，规划与实际执行各损失多少？
5. 新增抽屉技能、换用更强 LLM 或接入 chain-of-thought 时，框架是否能模块化扩展？

## 方法与数据

![SayCan 将语言相关性与技能可供性相乘](/images/literature-notes/saycan/method-overview.png)

*图 1｜给定高层指令，LLM 为每个候选技能给出任务相关性，价值函数根据当前机器人观测评估成功概率；乘积分最高的技能执行后被追加到提示词，系统再规划下一步。来源：原论文 Figure 2，PDF 物理页 4。[原文 PDF](https://proceedings.mlr.press/v205/ichter23a/ichter23a.pdf#page=4)*

### 1. 把每个自然语言技能视为一个 option

设高层指令为 $i$，当前环境状态为 $s$，技能 $\pi$ 的语言描述为 $l_\pi$。每个技能包含：

- 一个语言条件低层策略，负责执行有限时程的动作；
- 一个价值函数，近似当前状态执行该技能的成功概率；
- 一段可供 LLM 阅读的自然语言名字，如 `find an apple`、`pick up the apple`、`go to the table`。

语言模型评分为 $p(l_\pi\mid i)$：在给定指令与已选步骤的提示词中，哪段技能文本最可能成为下一步。价值函数被解释为可供性：

$$
p(c_\pi\mid s,l_\pi),
$$

其中 $c_\pi$ 表示技能 $\pi$ 可成功执行。论文另用 $c_i$ 表示“所选技能成功推进指令 $i$”这一事件；在“技能失败就不可能推进指令”的假设下，SayCan 将它近似分解为：

$$
p(c_i\mid i,s,l_\pi)
\propto
p(c_\pi\mid s,l_\pi)\,p(l_\pi\mid i).
$$

于是下一技能为

$$
\pi^*=\arg\max_\pi
p(c_\pi\mid s,l_\pi)\,p(l_\pi\mid i).
$$

左侧不是“指令完成概率”的完整生成模型，而是论文定义的“这个技能推进该指令”的成功概率。这一式也不是严格推导出的联合世界模型，而是工程上的 product-of-experts：只有同时“语言上有用”和“物理上可行”的技能才会得高分。两个分数的校准方式、相关性与尺度差异没有被理论解决。

### 2. 闭环仅发生在技能边界

推理循环为：

1. 把任务、少量示例以及候选技能名字放入 PaLM 540B 的提示词；
2. 对全部技能计算下一个语言片段的概率；
3. 从视觉观测计算每个技能的价值分数；
4. 选择乘积最大者并执行其低层策略；
5. 把已选技能文本追加到 LLM 上下文，再次评分；
6. 直到 LLM 选择终止标记。

系统会在每个技能完成后重新读取机器人状态并计算价值函数，因此比一次性生成整个计划更闭环。但状态没有被翻译成详细文本反馈给 LLM；失败原因、物体关系和不确定性大多只通过下一轮数值可供性间接体现。

### 3. 技能库与低层训练

论文使用 551 个候选技能，覆盖 7 类行为、17 类对象。低层模块主要来自两条路线：

- **BC-Z 行为克隆**：基于图像的语言条件策略。训练集合包括 11 个月内由 10 台机器人收集的约 68,000 条遥操作示范，以及约 276,000 条自主尝试；其中约 12,000 条成功轨迹加入 BC 数据。训练约用 16 个 TPUv3、27 小时。
- **MT-Opt / PI-QT-Opt 强化学习价值函数**：稀疏成功奖励，成功标签由三名标注者多数票确定。训练约用 16 个 TPUv3、100 小时，并行使用约 3,000 个 CPU episode workers 和 3,000 个 target-Q workers；模拟图像通过 RetinaGAN 做 sim-to-real 变换。

因此高层规划虽无需新训练，底层“可供性”背后依赖大规模机器人数据、自动采样基础设施和昂贵训练。论文并不是只靠一个 LLM 就获得机器人能力。

### 4. 训练与推理边界

| 组件 | 训练时 | 推理时 |
|---|---|---|
| LLM | 使用预训练 PaLM；SayCan 不微调 | few-shot 提示，为固定技能文本评分 |
| 低层策略 | BC-Z / MT-Opt 等从机器人轨迹学习 | 执行被选短技能 |
| 价值函数 | 从技能成功/失败经验学习 | 根据当前观测输出可供性分数 |
| 规划器 | 无额外学习 | 每个技能边界重算乘积并追加历史 |

## 实验

### 1. 主评测协议

- 101 条自然语言指令，覆盖 7 个指令族、15 个对象、5 个位置；
- 同时在训练用 mock kitchen 与真实办公厨房评测；
- 规划成功由人类判断技能序列是否完成指令，执行成功要求机器人真正完成；
- 三名评审中至少两名同意才记为成功；
- 对照包括去掉价值函数的 `No VF`、先由 LLM 自由生成再投影到技能的 `Generative`，以及直接使用自然语言或 USE 嵌入条件的 BC 策略。

![SayCan 的主实验结果](/images/literature-notes/saycan/main-results.png)

*图 2｜SayCan 在 mock kitchen 达到 84% 规划、74% 执行，在真实厨房达到 81% 与 60%；表格同时显示结构化、crowd-sourced、embodiment 与长时程子集。来源：原论文 Table 2，PDF 物理页 7。[原文 PDF](https://proceedings.mlr.press/v205/ichter23a/ichter23a.pdf#page=7)*

| 设置 | 规划成功率 | 执行成功率 |
|---|---:|---:|
| SayCan，mock kitchen | **84%** | **74%** |
| SayCan，真实 kitchen | **81%** | **60%** |
| No VF，mock kitchen | 67% | 未报告 |
| Generative，mock kitchen | 74% | 未报告 |
| BC NL，mock kitchen | 未单列 | 0% |
| BC USE，mock kitchen | 未单列 | 9% |

价值函数相对 `No VF` 提升 17 个规划百分点，支持可供性过滤的作用；但论文没有给出逐指令配对统计或置信区间，不能据此声称差异具有某个已验证的显著性水平。真实厨房从 81% 规划降至 60% 执行，21 个百分点的缺口表明即使计划正确，低层控制与感知仍会失败。

### 2. 最难子集与失败归因

- 长时程指令在 mock kitchen 为 73% 规划、47% 执行，在真实厨房同样为 73% 与 47%；链条越长，单技能错误越容易累积。
- embodiment 子集在 mock kitchen 为 64% / 55%，在真实厨房也是 64% / 55%，说明语义上需要理解“机器人能做什么”的指令仍较难。
- 作者把观察到的错误归因为约 **65% LLM 错误、35% 可供性错误**。语言侧包括否定表达、歧义指代和过早终止；可供性侧包括对物体或技能成功率判断错误。该比例是作者在有限失败样本上的归类，不是独立标注的大规模统计。

### 3. 新技能与 LLM 规模

新增 open/close/go-to-drawer 技能后，21 条抽屉查询的规划成功率为 **100%**，执行成功率只有 **33%**；作者明确将差距归因于串联操作策略失败。这很好地说明 SayCan 能快速把新技能接入高层菜单，但高层组合无法弥补不可靠的底层能力。

在不使用可供性的生成式规划对照中，PaLM 540B、PaLM 62B、PaLM 8B 与 FLAN 137B 的成功率分别为 74%、72%、38% 与 43%。完整系统中 PaLM 与 FLAN 的规划/执行为 84%/74% 和 70%/61%。模型规模和训练方式明显影响语言规划，但价值函数不能把弱语言模型完全补成强规划器。

论文还展示了接入 chain-of-thought 与多语言提示的案例。这些是能力示例，不是与主表同规模的系统定量评测，不能写成已证实的稳健泛化结论。

## 主要发现

1. **语言先验与可供性确实互补**：主表中完整乘积分数优于只用 LLM 的 `No VF`，尤其会压低与当前状态不相容的技能。
2. **高层计划优于端到端语言条件 BC**：固定技能组合让长任务从几乎不可用提升到可执行，但代价是依赖人工定义的技能接口。
3. **计划正确不代表任务成功**：真实厨房中 81% 到 60% 的下降，以及抽屉任务 100% 到 33% 的下降，都把瓶颈指向感知与低层控制。
4. **模块化扩展成立但有限**：新增一个带价值函数的技能即可进入规划；然而收集训练数据、定义终止条件和校准成功概率仍需大量工程。
5. **强 LLM 很重要**：较小 PaLM 或 FLAN 的下降说明可供性筛选无法替代语言理解本身。

## 结论

SayCan 给出了一个影响深远的接口设计：不要求 LLM 学会机器人动力学，而是让其提出“有用的技能”；不要求价值函数理解开放语言，而是让其回答“现在做得成吗”。在固定技能库内，这一分工比纯语言规划或纯语言条件控制更可靠，也自然支持在技能边界重规划。

更准确的研究定位是**LLM 引导的技能级具身规划器**。它既不是连续动作 VLA，也不是显式学习状态转移的世界模型；其环境 grounding 主要来自价值函数，而不是 LLM 自己理解视觉世界。

## 局限与适用边界

### 作者明确承认的局限

- LLM 继承互联网语料中的偏见、事实错误与分布外失效，语言分数也未针对机器人任务校准。
- 系统上限由固定技能库决定；不存在的技能无法被规划出来。
- 可供性估计与低层策略失败会直接破坏长时程链条，且错误会累积。
- 原始框架给 LLM 的环境反馈有限，对失败原因和连续状态缺少显式建模。
- 复杂否定、歧义引用与合适终止仍是主要语言错误来源。

### 额外证据审计

- 乘法因子分解默认语言相关性和成功概率可比较、近似独立，却没有校准实验；分数尖锐度变化可能改变决策。
- 101 条指令仍围绕相同厨房对象、技能和场景，不能代表开放世界家庭部署。
- “规划成功”依赖人类对生成技能序列的判断；论文没有发布完整逐项标签、评审一致性或盲评流程。
- LLM、训练数据和大量机器人基础设施均为闭源或未完全发布，官方 notebook 只复现桌面玩具版本。
- 系统没有形式化安全约束、碰撞验证或风险敏感目标；一个高乘积分数不等于动作安全。
- 没有与符号规划器、搜索式任务规划或带显式状态估计的完整强基线做同协议比较。
- 所谓 zero-shot 仅指新语言目标的技能组合；技能学习、价值估计与对象范围并非零样本。

## 我的思考

SayCan 最值得保留的思想不是某个具体 LLM，而是“**语义价值 × 具身价值**”的决策接口。后续工作可以沿三条线补足：

1. 把单一乘积升级为经过校准的不确定性模型，区分语言歧义、视觉缺失与技能失败风险；
2. 把技能执行后的结构化状态、失败原因与新观测显式写回规划器，形成真正的反馈闭环；
3. 在固定技能调用之外，允许受验证的代码组合或参数化空间目标，同时用安全 shield、运动规划器和运行时监控约束生成结果。

从今天的视角看，SayCan 也提供了一个有用基线：任何声称“LLM 能直接控制机器人”的方法，都应回答它相比一个强技能库加价值函数，究竟新增了哪些可验证能力，以及是否牺牲了可控性和安全边界。
