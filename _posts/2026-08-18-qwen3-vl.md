## 核心结论

Qwen3-VL 通过 Interleaved MRoPE、DeepStack 和显式文本时间戳扩展长视频与多层视觉融合，并在后训练中加入长 CoT、蒸馏、RL、GUI 和工具使用。实验同时表明，Thinking 对复杂 STEM 有益，却可能损害 OCR/文档任务；更多推理和更多视觉层都不是逐项必胜。

## 研究背景

Qwen2-VL 已解决任意分辨率与基本视频位置编码，但超长视频中三个位置轴被分配到不同频段，时间轴可能缺少足够的高低频覆盖；单次把最终 ViT 特征送入 LLM，也可能损失浅层文字和局部纹理。与此同时，多模态模型正从问答转向 GUI、代码、工具调用和“边看边思考”，要求视觉信息能在语言模型多层持续注入，并支持 256K 以上上下文。

Qwen3-VL 因而代表从“视觉助手”到“多模态推理与行动基础模型”的转向。其关键问题不再只是是否看清图片，而是长时序位置是否稳定、多层视觉证据是否保留、推理预算能否按任务选择，以及 dense/MoE 家族能否覆盖不同部署成本。

## 研究问题

动态分辨率解决了“看清”问题，但长文档、小时级视频、复杂视觉推理和 GUI 行动还要求多层视觉信息、稳定的长距离位置编码以及不同的推理预算。Qwen3-VL 试图用一个 dense/MoE 模型家族覆盖这些需求，并保持纯文本能力。

## 方法与数据

![Qwen3-VL 原生分辨率、DeepStack 与统一解码器](/images/literature-notes/qwen3-vl/method-overview.png)

*图 1｜Qwen3-VL 保留动态原生分辨率，在 LLM 多层通过 DeepStack 注入视觉 token，并在视频 token 前写入可读时间戳；解码器可选 dense 或 MoE。来源：原论文图 1。*

从信号路径看，视觉编码器先产生最终层与三个中间层特征；最终层经主 merger 进入普通上下文，中间层分别经独立 merger 对齐维度，再加到 LLM 前三层相应视觉位置的隐藏状态。Interleaved MRoPE 在注意力旋转维度中交错安排 t/h/w 频率；文本时间戳提供显式绝对时间。两者分别处理相对时空关系和可语言引用的绝对时刻，功能不能互相替代。

### 模型家族与视觉前端

家族包含 dense 2B/4B/8B/32B，以及 MoE 30B-A3B、235B-A22B；`A3B/A22B` 表示每 token 激活参数量。每个规模都发布 Instruct 与 Thinking 版本。视觉编码器由 SigLIP-2 继续训练而来，小型 LLM 使用约 300M 的 Large 视觉版本，其余默认约 400M；2×2 patch 经两层 MLP merger 合成一个语言侧视觉 token。

### 三个结构改动

- **Interleaved MRoPE**：Qwen2-VL 将 t/h/w 各占连续频段，可能让三个轴只看到特定高低频；Qwen3-VL 交错排列三个轴，使每一轴都覆盖完整频谱，目标是改善长视频位置建模。
- **DeepStack**：从 ViT 三个中间层取特征，各用独立 merger 映射后，以残差形式注入 LLM 前三层对应隐藏状态；不增加上下文长度，但增加视觉计算和跨层耦合。
- **文本时间戳**：不再只靠位置 ID 表示绝对时间，而是在视频 patch 前加入 `<3.0 seconds>` 或时分秒文本。它让时间可以被语言直接引用，代价是增加 token，并依赖模型正确解析格式。

### 四阶段预训练

S0 只训练 merger，使用 67B token、8K 上下文；S1 解冻全参数，以约 1T 图文/文本 token 在 8K 训练；S2 仍约 1T，但扩至 32K，并提高长文本、视频和 agent 数据比例；S3 用 100B 精选长文档/长视频数据适配 256K（表 1）。这意味着 256K 能力来自最后相对较小的专门阶段，不应假设全部 2T 级数据都按超长序列训练。

### 后训练

冷启动 SFT 约 120 万样本，混合短答案、普通 CoT 和长 CoT；随后从强模型向小模型蒸馏。在 reasoning RL 中，作者先筛掉初步 RL 收益有限的数据源，保留约 30k 可验证 queries，按数学、grounding、OCR、GUI 等任务组合规则或模型奖励；general RL 再优化指令遵循和主观质量。`Thinking with Images` 允许推理过程中调用裁剪/放大工具，但早期模型容易退化成只调用一次，作者用专门数据纠正。报告对数据生成教师、奖励权重和失败样本披露仍有限。

## 实验

### 评价范围

报告用大量公开和内部 benchmark 覆盖通用 VQA、视觉数学、文档/OCR、grounding、视频、多图、空间/具身、GUI/网页 agent，以及纯文本知识、代码和工具调用。最强结果通常来自 235B-A22B，但不同表分别比较 Instruct/Thinking，且闭源 API 的提示和日期不完全统一。阅读时应优先看同一模型内部对照与消融。

### Instruct 与 Thinking

![Qwen3-VL 旗舰模型多任务结果](/images/literature-notes/qwen3-vl/key-results.png)

*图 2｜旗舰 235B-A22B 与 Gemini、GPT-5、Claude 的视觉基准表。表格同时包含 Thinking/Instruct 与闭源模型不同推理预算；最有解释力的是同一 Qwen3-VL 两种模式的列内比较，而非跨 API 的绝对总排名。来源：原论文表 2。*

| 任务 | 235B-A22B Instruct | 235B-A22B Thinking | 说明 |
|---|---:|---:|---|
| MMMU | 78.7 | 80.6 | 复杂综合推理受益 |
| MathVista | 85.8 | 88.2 | 视觉数学受益 |
| DocVQA | 97.1 | 96.5 | 文档抽取轻微退化 |
| OCRBench | 920 | 875 | 纯 OCR 明显退化 |
| RealWorldQA | 83.7 | 83.2 | 基本持平/略降 |

这组结果表明 Thinking 是任务条件而非单调升级：需要多步推导时值得付出 token，检索/抄录型任务则可能被冗长推理干扰。报告没有给出按问题自动路由两种模式的系统实验。

### 视觉编码器与 DeepStack

Qwen3-ViT 在 ImageNet-1K/V2 与 SigLIP-2 接近（84.6/78.8 vs. 84.2/78.6），但内部 OmniBench 为 45.5 vs. 36.9；接同一 1.7B LLM、训练 1.5T token 后，OCRBench、AI2D、RealWorldQA、InfoVQA 也更高（表 11）。由于 Qwen3-ViT 本身经过额外数据和训练，提升不能只解释为架构。

DeepStack 在内部 15B-A2B、200B token、无后训练条件下将 12 项平均从 74.7 提至 76.0；InfoVQA 71.9→74.2、DocVQA 89.5→91.1，TextVQA 80.6→80.5（表 12）。消融较干净地支持多层视觉注入总体有效，同时保留了局部负项。

### 长上下文与视频

needle-in-a-haystack 把显著目标帧插入长视频，以 1 FPS 和恒定视觉 token 预算测试定位问答。256K/30 分钟范围为 100%；用 YaRN 外推到约 1M token/120 分钟时总体 99.5%（图 3）。这是强检索证据，但显著单帧 needle 不要求跨分钟整合状态、追踪多个相似对象或解释因果链。

### 规模与纯文本迁移

报告强调多模态训练没有损害、甚至常超过对应 Qwen3 文本骨干。例如 Qwen3-VL-32B-Instruct 在 MMLU-Pro/GPQA/AIME-25 为 78.6/68.9/66.2，对应 Qwen3-32B 为 71.9/54.6/20.2（表 7）。但 VL 模型还经过不同后训练与蒸馏，不能把差值视为“视觉数据自然提升语言”的单因素实验。

## 主要发现

1. **Thinking 适合复杂推理，但不是所有任务默认最优。** 旗舰 Thinking/Instruct 在 MMMU 为 80.6/78.7；DocVQA 为 96.5/97.1，OCRBench 为 875/920（论文表 2）。长推理对检索式文字任务可能带来额外扰动。
2. **DeepStack 总体有效但有负项。** 相同内部 15B-A2B、200B token 预训练下，12 项平均分从 74.7 提升到 76.0，InfoVQA 和 DocVQA 提升；TextVQA 则从 80.6 微降到 80.5（表 12）。
3. **长视频检索能力很强，但任务较窄。** video needle-in-a-haystack 在 256K/30 分钟内为 100%，使用 YaRN 外推到约 1M token/2 小时为 99.5%（图 3）。它只证明显著帧可被找回，不等于跨段因果理解。
4. **模型家族强调部署折中。** Dense/MoE、Instruct/Thinking 和多个规模提供不同延迟-质量选择，但报告没有在统一硬件上给出覆盖全部模式的成本曲线。

## 结论

作者把 Qwen3-VL 定位为从感知、推理到行动的一体化多模态基础模型：原生支持 256K 图文视频交错上下文，增强视觉与纯文本推理，并可作为 GUI、搜索和多模态编码等 agent 工作流的基础。

## 局限与适用边界

### 技术报告的证据边界

- 仍是团队发布的预印本，训练数据、教师模型、RL 细节和内部基准披露不足。
- Qwen3-VL 继承 Qwen2.5-VL 与 Qwen3 语言骨干，不能把 Qwen1/2/3 的差异归因于单一新组件。
- Thinking 与 DeepStack 都出现局部退化，不能根据总体平均分假设每个任务受益。
- Needle 实验是合成检索，不覆盖长视频中的事件计数、状态变化和因果推断。
- 旗舰 235B-A22B 的部署成本很高；报告没有在统一预算下与小模型或闭源 API 比较延迟、吞吐和显存。
- S0-S3 与多轮后训练同时改变数据、上下文、参数更新和奖励，除了 DeepStack 等少量消融，绝大多数代际提升无法做单因素归因。
- 视觉/GUI agent 评价多为受控基准；工具调用成功不等于面对网站变化、权限、延迟和不可逆操作时仍可靠。
- “Thinking with Images”依赖模型自选裁剪工具，报告没有系统给出调用成本、错误裁剪率和无用循环比例。
- 256K 是原生训练上限，1M 结果依赖 YaRN 外推；真实部署的显存、首 token 延迟和视频解码成本没有随长度完整报告。

## 我的思考

Qwen3-VL 的关键变化是把“视觉输入”升级为“可持续参与推理和工具操作的上下文”。更值得研究的是动态路由：先用 Instruct 快速完成 OCR 和文档提取，只在不确定或复杂问题上切换 Thinking、放大图像或调用搜索工具，而不是对所有任务固定使用最长上下文与最长 CoT。
