## 核心结论

AutoVLA 用 2048 项物理动作码本把连续轨迹接入语言模型，并用监督微调与 GRPO 学习“简单场景直接行动、复杂场景先推理”。同模型对照表明，动作 token 比文本坐标更准、更快；强化微调又同时提高 NAVSIM 分数并压缩推理时间，但最佳结果仍依赖奖励、仿真和 oracle 候选选择。

## 研究背景

端到端自动驾驶经历了从“感知—预测—规划”模块串联，到直接从传感器预测轨迹的转变。VLM 加入后，系统获得了描述场景、解释对象关系和利用开放世界知识的能力，但语言模型天然擅长离散 token，而车辆控制要求连续、平滑并满足动力学约束的数值序列。早期驾驶 VLM 因而常在两种方案之间取舍：把轨迹写成文本坐标，结构统一但数值不稳且解码慢；或外挂专用规划头，动作更合适却削弱语言推理与动作的统一优化。

另一条矛盾来自 CoT。复杂交互场景可能需要显式分析，直路跟车却不值得生成长理由。固定 CoT 会把语言解码延迟带进每个控制周期；完全取消推理又可能损失对长尾场景的判断。AutoVLA 的研究位置正是同时处理“动作表示”和“思考预算”这两个接口问题。

## 研究问题

已有驾驶 VLA 常见三类问题：文本坐标可能不满足物理约束，视觉语言模型外接复杂动作模块会破坏统一训练，而所有场景都生成长 CoT 又造成高延迟。AutoVLA 试图在同一自回归模型里统一“理由”和“动作”，并让策略自行决定思考预算。

## 方法与数据

![AutoVLA 模型与两阶段训练流程](/images/literature-notes/autovla/method-overview.png)

*图 1｜AutoVLA 的完整信息流。左侧小型 VLM 同时生成 reasoning token 与 action token；上方用 72B 教师蒸馏理由，右侧再以 GRPO、驾驶奖励和长度惩罚做强化微调。来源：原论文图 3。*

从训练到推理可以把模型拆成四步：多帧多视角图像经 Qwen2.5-VL 视觉编码器形成视觉 token；文本提示加入导航与自车运动状态；自回归解码器选择直接输出动作或先输出结构化理由；动作 token 最后查码本还原成连续轨迹。SFT 阶段同时学习两种输出路径，RFT 阶段不增加新的模式分类器，而是通过回报改变两条路径的相对概率。

### 模型输入与动作表示

AutoVLA 以 Qwen2.5-VL-3B 为骨干。输入包括前、左前、右前三个相机各 4 帧图像，采样频率为 2 Hz，即覆盖约 2 秒历史；文本侧还输入高层导航命令，以及速度、加速度和历史动作等自车状态。这个输入配置并非完整环视，因此模型对车后方信息的利用取决于数据集和任务设置。

作者不让语言模型直接逐字符输出浮点坐标，而是先用 K-disk 聚类建立 2048 项动作码本。每个 token 表示 0.5 秒内的相对位移与航向变化 `(Δx, Δy, Δθ)`，连续 10 个 token 解码成 5 秒轨迹。码本规模消融显示，2048 项时 ADE/FDE 重构误差为 0.0182/0.0203 m，运动覆盖率 99.42%、码本使用率 100%；继续增加到 4096 项虽略降误差，但使用率降至 91.46%（表 4）。

### 双模式监督微调

同一个自回归模型学习两种输出协议：fast-thinking 使用固定短模板后直接生成动作 token；slow-thinking 依次生成场景描述、关键对象、周围参与者意图、驾驶决策，再生成动作。CoT 由 Qwen2.5-VL-72B 在真实动作提示下自动标注，得到 nuPlan 45.6k 条、Waymo 7.2k 条理由数据，并把 DriveLM 的 nuScenes/CARLA 问答重排为相同结构。

SFT 同时优化全序列语言建模损失和只作用于动作位置的辅助损失。含 CoT 样本额外乘以权重 `λcot=40`，动作损失权重 `λa=1`，目的是避免数量更多的 action-only 样本淹没推理监督。SFT 训练 5 个 epoch，使用 8 张 L40S、有效 batch size 32。

### 强化微调

第二阶段用 GRPO 从每个场景采样一组候选，按组内相对奖励更新策略。驾驶奖励在 NAVSIM 使用 PDMS，在 Waymo 使用 ADE；总奖励再减去随 CoT 长度增加的惩罚，因此模型同时受到“轨迹更好”和“理由更短”的压力。RFT 冻结视觉编码器，用 LoRA 训练 6000 步；论文给出的关键参数包括 rank/alpha=8、KL 权重 0.04、长度正则权重 0.3。这里的“自适应思考”不是显式分类器，而是奖励塑造后输出分布发生变化。

### 数据规模

统一预处理后的训练/测试量分别为：nuPlan 166.3k/12.1k、nuScenes 19.0k/5.6k、Waymo 23.8k/1.5k；CARLA 训练 274.5k，闭环测试使用 Bench2Drive。不同数据集的相机数量并不完全一致，例如 CARLA 只用前视相机，这会给跨数据集比较带来配置差异。

## 实验

### 评价问题与协议

实验分别回答四个问题：动作 token 是否优于文本坐标；RFT 是否同时改善规划与时延；方法能否从开环迁移到闭环；各组件的收益是否稳定。开环使用 NAVSIM/nuPlan 的 PDMS、nuScenes 的 1/2/3 秒 L2 与碰撞率、Waymo 的人工 Rater Feedback Score；闭环使用 CARLA Bench2Drive 的 Driving Score、Success Rate、Efficiency 和 Comfortness。NAVSIM 的 Best-of-N 从 6 条候选中用 oracle scorer 选最优，必须与单次在线输出分开解读。

论文还报告 RFT 后 500 个 NAVSIM 场景平均运行时间下降 66.8%。但模式级时延差异很大：fast-thinking 约 1.07 秒，slow-thinking 约 10.52 秒，说明“平均更快”主要来自减少慢模式频率，而不是慢推理本身已满足车端实时控制。

### 消融与稳健性

动作码本在 2048 项后进入收益递减区，支持作者的容量选择。CoT 数据规模实验则显示，nuPlan 训练样本少于约 5 万时，理由监督并不稳定优于纯动作；只有数据量上升后才体现收益。Waymo 结果显示跨 nuPlan/nuScenes 预训练、加入 CoT、再做 ADE 奖励 RFT 逐步改善 RFS，但图中没有像 NAVSIM 表格那样完整披露所有绝对数值。闭环比较虽然比纯开环更强，但 AutoVLA 与 ORION 的数据与训练配方不同，差值不能直接归因于动作 token 或 RFT。

## 主要发现

1. **物理动作 token 优于文本航点。** 相同混合训练集上，文本坐标输出的 PDM Score 为 71.31、平均 L2 0.89 m、碰撞率 0.36%、运行时间 7.65 s；物理动作 token 为 80.54、0.70 m、0.31%、3.95 s（论文表 5）。
2. **RFT 同时改善奖励指标与推理成本。** NAVSIM 上 one-shot PDMS 从 80.54 提升到 89.11；项目和论文报告相对改善 10.6%，500 个测试场景平均运行时间下降 66.8%（表 1、图 5）。
3. **Best-of-N 不是普通在线结果。** 从 6 个候选中用 oracle scorer 选优时 PDMS 为 92.12（表 1）；它说明候选分布含有更好轨迹，但不能作为单次在线策略成绩。
4. **闭环证据优于纯开环，但仍是仿真。** Bench2Drive/CARLA 中 AutoVLA 为 78.84 DS / 57.73% SR，高于论文对照 ORION 的 77.74 / 54.62（表 3）；两者训练配置不同，不能据此形成稳定总排名。
5. **CoT 需要足够数据。** 数据规模实验显示，在 nuPlan 样本少于约 5 万时，CoT 监督并不优于只学动作；规模增加后结构化推理才稳定受益。

## 结论

作者认为，物理动作词表可以保留自回归 VLM 的统一结构，同时避免直接生成精确数值的缺点；任务奖励与长度惩罚驱动的 RFT 则能形成按场景复杂度切换的自适应推理策略。

## 局限与适用边界

### 作者明确承认的局限

- 快模式平均仍约 1.07 秒，慢模式平均约 10.52 秒（表 2），距离高频车端控制仍有明显差距。
- 作者把当前系统概括为接近 1 Hz，仍高度依赖 GPU 显存和算力，并把量化和车端加速列为后续方向。

### 精读后识别的额外边界

- RFT 直接优化 NAVSIM/Waymo 指标，提升可能包含对奖励协议的适配；跨评价集稳健性需要额外验证。
- Best-of-N 需要 oracle scorer，无法作为部署时无需额外信息的结果。
- CoT 大量由强 VLM 自动标注，可能继承教师偏差；官方仓库也标明 reasoning data 尚待审批。
- 闭环测试是 CARLA 仿真，尚未覆盖真实传感器故障、天气、标定漂移与安全冗余。
- 动作码本约束的是训练分布内短轨迹原型，并不等同于经过车辆动力学、安全走廊或交通规则求解器验证；少见危险动作可能正是聚类覆盖最弱的尾部。
- 输入只含三个前向相机，且不同数据集相机配置不一致，论文未系统隔离视野差异对结果的影响。

## 我的思考

AutoVLA 真正有价值的是把“是否思考”也变成策略的一部分。更合理的后续方向不是一味压缩 CoT，而是根据模型不确定性、场景风险和安全层反馈决定推理深度；动作码本还应报告覆盖率之外的尾部重构误差，避免少见但危险的轨迹被聚类平均掉。
