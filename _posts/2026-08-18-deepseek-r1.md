## 核心结论

论文必须分开读两个模型。**DeepSeek-R1-Zero** 从 DeepSeek-V3-Base 出发，不先做 SFT，只用数学、代码、逻辑等可验证问题的结果/格式奖励和 GRPO。训练中 AIME 2024 pass@1 从 15.6% 增到 77.9%，输出长度同步增加，并出现自检、回溯和“aha moment”式文本。这个实验说明：足够强的基座、可靠 verifier 和大规模在线采样可以把潜在能力转成更长的解题轨迹。

**DeepSeek-R1** 是为解决 R1-Zero 的可读性、语言混杂和通用能力问题而设计的多阶段模型：数千条冷启动 SFT → 第一阶段 reasoning RL → 拒绝采样并混入通用数据的第二次 SFT → 同时覆盖推理、帮助性与安全的第二阶段 RL。最终结果不能用“没有人类数据的纯 RL”概括；纯 RL 是 R1-Zero 的研究对照，R1 本身明确使用人工/模型构造数据与 reward model。

R1 的计算表在 arXiv v2 给出：R1-Zero 101K、SFT 数据创建 5K、R1 41K，共 **147K H800 GPU-hours**，按 2 美元/GPU-hour 为 294K 美元。该表不包含前期 30B/A100 研究、失败试验、V3 Base 的预训练、人员、数据与部署；它是 R1 后训练主运行的账单，不是“从零训练 R1”或整个项目的总成本。

## 研究背景

传统 RLHF 往往先用人工示范做 SFT，再训练 reward/value model，最后用 PPO 对齐。对长链推理而言，这一路线有两个困难：人类高质量推理轨迹昂贵且可能把模型限制在示范风格；只在回答末尾得到 outcome reward 时，value model 要从尚未完成、可能后来自我修正的前缀预测最终回报，训练并不容易。

数学和程序任务提供了一个特殊机会：最终答案、单元测试或编译器能给出相对精确、可扩展的 reward，而不必逐步标注每一行推理。DeepSeek-R1 的问题因此不是“CoT 提示是否有用”，而是“能否直接优化最终可验证结果，让模型自己探索长推理行为”。它承接 [DeepSeek-V3](/posts/deepseek-v3/) 的 671B/37B-active Base 和 [DeepSeek-V2](/posts/deepseek-v2/) 已使用的 GRPO，再把在线 RL 规模化。

## 研究问题

1. 不经过 reasoning SFT，单靠 outcome/format reward 和 GRPO，强基座能否学会更长、更有效的推理？
2. 为什么 GRPO 相对 PPO 更适合超大、长输出模型，省掉 value model 的代价和边界是什么？
3. 如何把 R1-Zero 的数学/代码能力转成可读、语言一致、会遵循指令且更安全的通用模型？
4. 多阶段流水线的每一步分别改善 reasoning、instruction following、工程代码或人类偏好中的哪一项？
5. 教师生成轨迹能否把推理能力迁移到 1.5B–70B 学生模型？纯 RL 对小模型是否同样有效？

## 方法与数据

### 1. GRPO：用组内相对回报替代 value model

对问题 $q$，旧策略 $\pi_{old}$ 采样一组回答 $o_1,\ldots,o_G$，按组内 reward 标准化得到：

$$
A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}
{\operatorname{std}(r_1,\ldots,r_G)}.
$$

令 $\rho_i=\pi_\theta(o_i\mid q)/\pi_{old}(o_i\mid q)$，GRPO 使用 PPO 风格裁剪并惩罚相对参考策略的 KL：

$$
J_{\mathrm{GRPO}}(\theta)=\mathbb E\left[
\frac1G\sum_{i=1}^{G}
\min\left(\rho_iA_i,
\operatorname{clip}(\rho_i,1-\epsilon,1+\epsilon)A_i\right)
-\beta D_{KL}(\pi_\theta\|\pi_{ref})
\right].
$$

论文使用的无偏 KL 估计可写为：

$$
D_{KL}(\pi_\theta\|\pi_{ref})
=\frac{\pi_{ref}(o_i\mid q)}{\pi_\theta(o_i\mid q)}
-\log\frac{\pi_{ref}(o_i\mid q)}{\pi_\theta(o_i\mid q)}-1.
$$

与 PPO 的关键差别是：GRPO 不训练与 policy 同量级的 value model，而从同一问题的多条 rollout 分数估计相对优势。代价是必须为每个问题采样多条长输出；当组内 reward 方差很小、verifier 有误或问题难度不均时，相对优势也会噪声化。因此“无 critic”不等于 RL 便宜，论文也没有给出 V3 全尺寸上同等效果的 PPO 总成本对照。[扩展报告 §2.1、Appendix A.3](https://arxiv.org/pdf/2501.12948#page=2)

### 2. R1-Zero：纯 RL 实验

初始化为 DeepSeek-V3-Base，prompt 只规定把推理和答案分别放进 `<think>` / `<answer>`，不提供解题示范。reward 主要有两类：

- **accuracy reward**：数学最终答案按规则核验，程序由 compiler/test cases 检验；
- **format reward**：检查输出是否遵守 think/answer 标签。

作者避免以神经 process reward model 逐步判分，原因是中间步骤边界难定义、自动标注不可靠且容易 reward hacking。R1-Zero 超参为学习率 $3\times10^{-6}$、KL 系数 0.001、rollout temperature 1；每题 16 个输出，step 8.2K 前最大 32,768 token、之后 65,536；共 10,400 step、约 1.6 epoch。每 step 32 个独立问题，group 后 batch 512；每 400 step 用当前 policy 更新 reference。每次 rollout 生成 8,192 个输出，切成 16 个 minibatch，只做 1 个 inner epoch。[扩展报告 §2](https://arxiv.org/pdf/2501.12948#page=2)

![DeepSeek-R1-Zero 训练曲线](/images/literature-notes/deepseek-r1/r1-zero-training.png)

*图 1｜R1-Zero 的 AIME 2024 pass@1/cons@16 与平均输出长度随 RL step 增加；8.2K step 同时把最大生成长度从 32K 提到 65K，曲线跳变因此不能全归因于策略“突然涌现”。来源：原论文 Figure 1，PDF 第 4 页。[扩展报告 PDF](https://arxiv.org/pdf/2501.12948#page=4)*

Figure 1 中 AIME pass@1 从 15.6% 到 77.9%，cons@16 为 86.7%。作者把训练中出现的重读题目、自检、替代解法和 “wait” 等行为解释为 self-evolution/aha moment。它们是可观察文本模式，却不是忠实内部推理的因果证明：论文没有干预删除这些片段来测答案变化，AIME 又被用作主要 validation set，因而训练曲线不能等同于未见分布泛化。

### 3. DeepSeek-R1 的四段流水线

![DeepSeek-R1 多阶段训练流水线](/images/literature-notes/deepseek-r1/pipeline.png)

*图 2｜最终 R1 的阶段：冷启动 SFT 得到 Dev1；可验证 reasoning RL 得到 Dev2；拒绝采样的 reasoning 与通用数据再 SFT 得到 Dev3；最后混合规则、偏好和安全 reward 做 RL。来源：原论文 Figure 2，PDF 第 6 页。[扩展报告 PDF](https://arxiv.org/pdf/2501.12948#page=6)*

1. **冷启动 SFT**：收集“数千条”可读、格式统一的长 CoT，先让 V3 Base 进入对话式推理分布；精确数量未公布。
2. **第一阶段 reasoning RL**：规则 reward + language consistency reward。后者定义为目标语言词数/总词数，以缓解中英混杂。学习率 $3\times10^{-6}$、KL 0.001、temperature 1、每题 16 rollout、最大 32,768、batch 512；报告把 GRPO clip ratio $\epsilon$ 设为 10。语言一致性会轻微损害部分代码结果，是可读性—纯能力取舍。
3. **拒绝采样 + 第二次 SFT**：从 RL checkpoint 生成 reasoning trajectories，按规则/模型筛选，并混入写作、事实问答、角色扮演和工程代码等 non-reasoning 数据。扩展版统计共 **804,745** 个样本，多为单轮：Math 395,285、Code 211,129、STEM 10,124、Logic 10,395、General 177,812；平均每样本 5,355 token。SFT 2–3 epochs，学习率由 $5\times10^{-5}$ cosine 降到 $5\times10^{-6}$，最大 32,768，batch 128。
4. **第二阶段 RL**：推理问题继续用 rule reward；通用问题用 helpful/safety reward model，加格式与语言 reward。temperature 降为 0.7，共 1,700 step；通用数据与偏好 reward 只在最后 400 step 加入，因为更长训练出现 reward 上升、Codeforces 性能下降的 reward hacking。

这条流水线解释了为何“R1 是纯 RL”不准确：R1-Zero 是纯 RL 研究分支，最终 R1 使用两次 SFT、拒绝采样、reward models 和人工规则。

### 4. Helpful / Safety reward model

helpful RM 有 66K preference pairs。每对回答由 DeepSeek-V3 交换 A/B 位置后判断 4 次，取平均，只保留分差 $\Delta>1$ 的 pair，并平衡 chosen/rejected 长度；prompt 来自公开集或明确同意用于改进模型的用户。训练 batch 256、学习率 $6\times10^{-6}$、1 epoch、最大 8,192。Safety RM 使用 106K “safe/unsafe” 点式样本，超参相同；helpfulness 只评价 final summary，safety 评价 reasoning 与 summary 全文。[扩展报告 §3.1](https://arxiv.org/pdf/2501.12948#page=6)

这种设计降低位置/长度偏差，但 judge 和 policy 同属 DeepSeek 模型家族，可能共享风格偏好与错误；只保留大分差样本也会偏向容易判断的 preference。

### 5. 蒸馏

作者用约 800K 个 R1 生成样本只做 SFT，分别训练 Qwen2.5-Math/Qwen2.5/Llama 基座的 1.5B、7B、8B、14B、32B、70B 学生。它不是 logit-level distillation，而是“教师轨迹数据微调”。学生继承教师输出、筛选规则和 benchmark 风格；性能提高证明高质量轨迹可迁移，不证明学生拥有与 671B 教师相同的机制或泛化边界。

### 6. 训练算力

扩展报告称 R1-Zero 使用 **64×8=512 张 H800**，约 198 小时，即约 101K H800-hours；R1 使用同样 512 张 H800，约 80 小时，即约 41K；SFT 数据创建 5K。合计：

| 项目 | H800 GPU-hours | 按 USD 2/GPU-hour 换算 |
|---|---:|---:|
| DeepSeek-R1-Zero | 101K | USD 202K |
| SFT 数据创建 | 5K | USD 10K |
| DeepSeek-R1 | 41K | USD 82K |
| **合计** | **147K** | **USD 294K** |

报告另称前期用 A100 做过 30B 小模型研究，但未纳入这张 H800 表；V3 Base 的 14.8T 预训练成本也属于另一个报告。故 294K 美元不能描述“R1 从原始数据训练完成”的成本。[扩展报告 Appendix B.4.4](https://arxiv.org/pdf/2501.12948#page=34)

## 实验

### 1. 阶段消融：能力不是单调上升

Table 3 沿流水线报告 R1-Zero → Dev1 → Dev2 → Dev3 → R1。关键变化如下：

| 指标 | R1-Zero | Dev1 冷启动 | Dev2 reasoning RL | Dev3 二次 SFT | 最终 R1 |
|---|---:|---:|---:|---:|---:|
| IF-Eval | 46.6 | 71.7 | 72.0 | 78.1 | **83.3** |
| GPQA Diamond | **75.8** | 66.1 | 70.7 | 71.2 | 71.5 |
| LiveCodeBench | 50.0 | 57.5 | 63.5 | 64.6 | **65.9** |
| Aider-Polyglot | 12.2 | 6.7 | 25.6 | 44.8 | **53.3** |
| AIME 2024 | 77.9 | 59.0 | 74.0 | 78.1 | **79.8** |
| AlpacaEval 2.0 LC | 24.7 | 50.1 | 55.8 | 62.1 | **87.6** |

冷启动立刻改善指令遵循，却使 AIME/GPQA 明显下降；reasoning RL 恢复推理；混合 SFT 对工程代码和通用偏好帮助大；最终 RL 主要拉升 AlpacaEval/ArenaHard。该表比最终总分更重要，因为它证明每阶段解决不同目标，并暴露 trade-off。阶段间训练数据也在变化，故不能把相邻差值当作单一算法的纯因果效应。[扩展报告 Table 3](https://arxiv.org/pdf/2501.12948#page=8)

### 2. 与闭源模型比较

扩展报告 Table 8 中，R1 的 AIME 2024 79.8、MATH-500 97.3、LiveCodeBench 65.9，论文引用的 OpenAI o1-1217 分别为 79.2、96.4、63.4；R1 的 GPQA Diamond 71.5 低于 75.7，Aider 53.3 低于 61.7。作者明确说明因在中国大陆访问 o1-1217 困难，o1 数字来自 OpenAI 官方报告，而非同一可执行 API 复测。所谓“达到 o1 水平”只在所列数学/算法题成立，不能外推到知识真实性、工具、工程代码或总体用户效用。[扩展报告 Table 8](https://arxiv.org/pdf/2501.12948#page=40)

R1 评测通常以 temperature 0.6、top-p 0.95 对每题采样 4–64 次，再把样本正确率平均为 pass@1；AIME/GPQA 用 64 样本。这比单次 greedy 稳定，但消耗更多推理计算，也使结果与只调用一次的产品体验不同。

### 3. 蒸馏结果

R1-Distill-Qwen-1.5B 的 AIME pass@1 为 28.9；32B 为 72.6，MATH-500 94.3、GPQA 62.1、LiveCodeBench 57.2。32B 直接做 10K+ step RL 的 Qwen2.5-32B-Zero，在表内 AIME 47.0、MATH 91.6、GPQA 55.0、LiveCodeBench 40.2，低于蒸馏版。[扩展报告 Tables 15–16](https://arxiv.org/pdf/2501.12948#page=60)

这说明在本文预算和基座下，强教师轨迹比让 32B 从头通过 RL 探索更有效；它不证明“蒸馏总是优于 RL”。训练计算、数据难度和搜索空间不同，作者还报告 7B/16B 起初无法从长 RL 获得有效 AIME 增益，说明纯 RL 对基座容量与初始能力高度敏感。

### 4. 安全与失败实验

论文报告 R1 内在安全总体为“中等”、与指定版本 GPT-4o 大致相当；配合外部风险控制系统后更高。作者同时指出 reasoning 能力会让越狱后有害计划更可执行，开放权重还可被再次微调移除保护。安全结论依赖内部/公开 benchmark 和特定风险系统，不能被理解为部署安全保证。

失败路线也很有信息量：Process Reward Model 难定义通用步骤、难可靠标注且容易被 hack；MCTS 面临 token 分支指数爆炸、局部最优和 value model 难训练。作者没有说 PRM/MCTS 永远无效，只报告它们在本次大规模训练中的收益不足以覆盖复杂度。[扩展报告 Appendix G.2](https://arxiv.org/pdf/2501.12948#page=63)

## 主要发现

1. **纯 RL 结论只属于 R1-Zero。** 它证明 verifier-guided exploration 可在强基座上提升可验证推理；最终 R1 是 SFT 与 RL 的迭代组合。
2. **GRPO 省掉 critic，不省 rollout。** 组内相对优势适合终局 reward 和长输出，但依赖多样本采样、稳定 verifier 与足够组内差异。
3. **长 CoT 是伴随现象，不是已证实机制。** 输出长度、自检文本与准确率共同增长；Figure 1 还受 8.2K step 最大长度变更影响，没有证明可见 CoT 忠实或自检片段导致正确。
4. **不同训练阶段解决不同目标。** 冷启动换可读性，reasoning RL 换数学代码，第二次 SFT 补通用/工程能力，末段 RL 对齐偏好与安全；其中存在可测的回退。
5. **蒸馏是能力扩散路线。** 高质量教师轨迹能让小模型显著增强，但能力、风险和数据偏差也一起被迁移。

## 局限与适用边界

### 作者明确报告的局限

- 结构化输出与工具使用弱，尚不能原生调用搜索、计算器等工具；
- 简单问题仍可能 overthink，token efficiency 有优化空间；
- 主要优化中文与英文，其他语言易出现语言混杂；
- 对 prompt 敏感，few-shot 往往使性能下降，作者建议 zero-shot；
- 软件工程任务评测慢，未进行足够大规模 RL，因此相对 V3 改善有限；
- 纯 RL 的可扩展性依赖可靠 reward，开放式写作等难验证任务容易 reward hacking；
- safety 有越狱和开放权重再微调风险，内在安全只达到报告所称中等水平。[正式论文](https://www.nature.com/articles/s41586-025-09422-z) · [扩展报告 §5–6](https://arxiv.org/pdf/2501.12948#page=9)

### 额外证据边界

- **基座依赖强**：7B/16B 初期实验未获有效提升，不能把 R1-Zero 结果推广为“小模型只用 RL 也会自然学会推理”。
- **verifier 覆盖有限**：数学最终答案和代码测试可判定，开放问答、研究、写作和伦理判断没有同样可靠的 reward。
- **可见 CoT 不保证忠实**：模型可能事后合理化；论文没有内部状态或因果干预证明 `<think>` 是实际决策过程。
- **AIME 的角色重叠**：AIME 既是主要 validation 观察指标又是最终代表 benchmark，可能产生研究选择偏差；作者的 n-gram 去污染不能排除释义和概念级泄漏。
- **闭源比较不完全同协议**：o1-1217 数字来自官方报告，API、prompt 和采样不可完全统一。
- **总成本更大**：147K H800-hours不含 V3 Base 预训练、A100 小模型研究、失败试验、数据/人员和部署；不是从零成本。
- **复现材料不完整**：开放权重与基础推理代码，但没有 RL/SFT 数据、verifier、reward model 和训练平台；独立团队无法逐项复现阶段结果。
- **多轮数据不足**：804,745 个 SFT 样本平均约 1.0 轮，扩展报告明确说这可能限制多轮对话。

## 路线关系

[DeepSeek LLM](/posts/deepseek-llm/) 建立中英基座与 scaling；[DeepSeek-V2](/posts/deepseek-v2/) 引入 MLA、MoE 和 GRPO；[DeepSeek-V3](/posts/deepseek-v3/) 提供 671B/37B-active 强基座与高效训练/推理接口；R1 将 GRPO 从通用对齐扩展成大规模 verifier-based reasoning RL。最终 R1 的生成轨迹又被用于 V3 Chat 后训练和 Qwen/Llama 学生蒸馏，形成“强基座 → 在线探索 → 筛选轨迹 → 多模型迁移”的闭环。

## 我的思考

R1 最值得保留的不是“aha moment”故事，而是任务可验证性决定训练范式：有可靠 outcome verifier 时，RL 可以探索超出人工示范的路径；没有可靠 verifier 时，SFT、人工偏好和风险控制仍不可替代。R1 的多阶段流水线本身已经否定了“纯 RL 可解决所有对齐”的强版本。

下一步的关键实验不是再展示更长思维链，而是进行干预：在语义等价条件下截断/替换反思段，测答案和校准；对同一训练问题设置隐藏测试与 adversarial verifier；用独立评审、多个随机种子和完整 rollout 成本比较 GRPO/PPO；发布足以复现的小规模数据与训练代码。这样才能区分“更长的可见文本”“更强的搜索策略”和“真正可迁移的推理能力”。

## 结论

DeepSeek-R1 提供了目前最完整的开放 reasoning 路线之一：R1-Zero 隔离出纯 RL 的可行性，最终 R1 则诚实地用多阶段 SFT/RL 修正纯 RL 的行为缺陷。数学和算法代码结果强、阶段消融和成本账单具体，Nature 正式发表进一步提升了文献地位；但 reward 可验证范围、CoT 忠实性、基座依赖、闭源对照、训练开放性和总成本边界必须同时保留。准确的结论不是“推理自动涌现且无需数据”，而是“强基座在可靠 verifier 和足够在线计算下可通过 RL 探索推理，再由监督与偏好数据把它变成更可用的模型”。
