## 核心结论

GR00T N1.7 是一个约 3B 参数、面向跨具身操作的 VLA 版本。其最清楚的技术变化是：用 Cosmos-Reason2-2B（Qwen3-VL 架构）替换 N1.6 的 Eagle 视觉语言骨干，以高层 action token 连接 flow-matching DiT 动作头；同时用相对末端执行器（relative EEF）表示对齐人类与机器人动作，并把 20,854 小时 EgoScale 人类第一视角视频纳入预训练。可下载 checkpoint 的配置和发布博文给出的动作头为 32 层，但固定 release tag / 当前通用代码默认值为 16 层；因此本文只把“32 层”绑定到这个公开 checkpoint，不泛化为所有 N1.7 配置。[官方发布页](https://huggingface.co/blog/nvidia/gr00t-n1-7)；[官方仓库“What's New”](https://github.com/NVIDIA/Isaac-GR00T#whats-new-in-gr00t-n17)；[checkpoint 配置](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/config.json)

公开结果支持一个较窄的判断：**经各基准专门后训练的 N1.7 checkpoint** 在当前官方 SimplerEnv 表中，Bridge 平均成功率由 N1.6 的 56.6% 升至 62.3%，Fractal 由 52.0% 升至 72.5%；但 Bridge 中仍有两个任务分别下降 36 和 31 个百分点。因此，资料支持“若干模拟基准的平均值改善”，不支持“所有任务一致改善”，更不能据此证明基础 checkpoint 已在未见机器人或真实工厂中可靠泛化。[官方 SimplerEnv 结果表](https://github.com/NVIDIA/Isaac-GR00T/blob/main/examples/SimplerEnv/README.md#benchmark-results)

证据等级低于一篇完整论文：没有 N1.7 专属方法论文、受控消融、误差条、独立复现或完整真机成功率表；官方页面还存在架构描述、数据口径、发布阶段、基准数字和许可证之间的版本冲突。它是一份可运行、可检查的工程发布，尚不是一套闭合的论文级证据链。

## 研究背景

通用机器人策略面临的数据瓶颈与动作空间错位。机器人遥操作数据昂贵，而且不同机械臂、人形机器人与灵巧手的自由度、坐标系和控制频率不一致；人类视频虽然规模大，却没有天然的机器人关节命令。N1.7 的背景假设是：如果把人手/手腕运动与机器人末端执行器统一到相对动作空间，大规模人类第一视角视频就能成为机器人预训练数据，而不必为每个技能都先收集同等规模的真机遥操作。

N1.7 还试图处理长时任务的两种时间尺度：VLM 负责根据图像和指令形成任务/子任务级 action token，DiT 负责把这些高层条件和实时本体状态转成连续动作块。这个“慢推理、快控制”的 Action Cascade 延续 N1 的双系统思想，但 N1.7 更换了 VLM、扩大了动作 horizon，并把人类视频对齐和部署工具链作为版本重点。[官方发布页“Action Cascade”](https://huggingface.co/blog/nvidia/gr00t-n1-7#what-is-gr00t-n17)

NVIDIA 将 EgoScale 作为 N1.7 人类视频预训练的直接研究基础。EgoScale 官方页面报告 20,854 小时、20 多类任务的人类第一视角数据，并展示验证损失随 1k–20k 小时数据呈近似对数线性缩放；这些是 **EgoScale 研究的结果**，用于解释 N1.7 的数据来源，不能自动视作 N1.7 基础模型的独立消融结果。[EgoScale 官方项目页](https://research.nvidia.com/labs/gear/egoscale/)

## 研究问题

这组官方资料实际围绕五个问题展开：

1. 能否用统一的 relative EEF 表示，把大规模人类手腕/手部运动先验迁移到不同机器人？
2. Cosmos-Reason2-2B 能否提供比 Eagle 更强的原生分辨率视觉编码、语言跟随与任务分解能力？
3. 高层 action token 与低层 flow-matching DiT 的串联，能否同时覆盖长时任务推理和连续运动控制？
4. 基础 checkpoint 能否适配多种具身，并通过 LeRobot 数据、后训练、ONNX/TensorRT 导出形成完整部署路径？
5. 与 N1.6 相比，N1.7 在公开基准上是否更好；这种提升是一致的基础模型增益，还是依赖任务专门后训练的局部结果？

前四项主要由架构、代码和部署资料回答；第五项只能由有限的官方基准表部分回答。没有独立论文意味着“为什么有效”和“每项改动贡献多少”仍缺少受控实验。

## 方法与数据

![GR00T N1.7 Action Cascade 架构](/images/literature-notes/gr00t-n17/method-overview.png)

*图 1｜N1.7 的 Action Cascade 概念示意：图像与语言先经 System 2 视觉语言模型形成高层表示/action token，System 1 扩散 Transformer 再结合机器人状态迭代去噪，输出连续电机动作。来源为 2026-07-07 NVIDIA 技术博客 Figure 2，已保存为本地 PNG。它不是独立论文中的完整架构图，也没有标出 Cosmos-Reason2/Qwen3-VL、relative EEF、40 步 horizon 或 DiT 层数；这些细节以下文 checkpoint 与代码为准。[原始页面](https://developer.nvidia.com/blog/develop-humanoid-robot-policies-end-to-end-with-nvidia-isaac-gr00t/#get-started-with-gr00t-1-7)*

### 1. 输入、输出与参数规模

N1.7 接受一幅或多幅 RGB 图像、自然语言指令、机器人本体状态和 embodiment ID，输出与该具身自由度对应的连续动作块。官方基础 checkpoint 为约 3B 参数、BF16；checkpoint 配置把最大状态维度与最大动作维度均设为 132，最大动作 horizon 为 40。[官方模型卡](https://huggingface.co/nvidia/GR00T-N1.7-3B)；[checkpoint `config.json`](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/config.json)

这里的 40 是“单次可预测的未来动作步数上限”，部署时可以只执行其中一部分再重规划。官方策略指南把 16 步用于 open-loop 评价、8 步列为实时部署的常见值；因此 horizon 不等于机器人控制频率，也不能仅由 40 推断闭环时延。[官方 Policy Guide](https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/policy.md)

### 2. System 2：Cosmos-Reason2-2B / Qwen3-VL

System 2 把图像 token 和语言指令编码为高层 action token，并承担任务及子任务分解。N1.7 用 Cosmos-Reason2-2B（Qwen3-VL 架构）替换 N1.6 的 Eagle，支持灵活分辨率和原生宽高比、无需先把所有图像填充到同一比例。官方 checkpoint 配置给出 2048 维骨干表示，并选择中间层表征供动作头使用。[官方仓库变更说明](https://github.com/NVIDIA/Isaac-GR00T#key-changes-from-n16)；[模型配置源码](https://github.com/NVIDIA/Isaac-GR00T/blob/main/gr00t/configs/model/gr00t_n1d7.py)

模型卡的同一“Architecture”段落又写“SigLIP2 处理图像、T5 编码文本”，并把名为 Cosmos-Reason2-2B 的链接指向 8B 页面；这与发布页、checkpoint 配置和部署文档不一致。本文以 **N1.7 checkpoint 配置 + 部署代码** 为版本特定证据，不把 SigLIP2/T5 描述当作 N1.7 已核实结构。

### 3. System 1：flow matching 动作头

System 1 是以当前机器人状态和 System 2 表示为条件的动作生成器。可下载 `GR00T-N1.7-3B` checkpoint 与当前部署文档给出 32 层 `AlternateVLDiT`、32 个注意力头、AdaNorm 条件化和 4 个推理去噪步；动作编码器/解码器按具身处理不同自由度，另有状态编码器和 4 层视觉语言自注意模块。[官方 checkpoint 配置](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/config.json)；[部署组件表](https://github.com/NVIDIA/Isaac-GR00T/blob/main/scripts/deployment/README.md#tensorrt-acceleration)

这里有一个不能忽略的版本冲突：2026-04-17 发布博文同样写“32-layer DiT”，但 `n1.7-release` 固定 tag 与当前 `gr00t_n1d7.py` 的通用默认配置均写 16 层，仓库兼容性说明还称 N1.7 相对 N1.6 从 32 层改为 16 层；与此同时，实际 checkpoint 的 `config.json` 和 TensorRT 部署组件表又是 32 层。最可能的工程解释是 checkpoint 加载时覆盖通用默认值，但官方没有给出勘误。因此，复现公开权重应以其 `config.json` 的 32 层为准；新建配置或比较“版本架构”时则必须同时记录代码 commit，不能混用。[固定 release tag 的配置](https://github.com/NVIDIA/Isaac-GR00T/blob/n1.7-release/gr00t/configs/model/gr00t_n1d7.py)；[当前兼容性说明](https://github.com/NVIDIA/Isaac-GR00T#detailed-compatibility-notes)

可将数据流概括为：

$$
(I_t,\ell) \xrightarrow{\text{Cosmos-Reason2}} z_t,
\qquad
(z_t,s_t,a_t^{\tau},\tau) \xrightarrow{\text{DiT}} \hat v_t
\xrightarrow[4\ \text{steps}]{\text{denoise}} \hat a_{t:t+H}.
$$

其中 (I_t) 是图像， (ℓ) 是语言，(s_t) 是本体状态，(a_t^{\tau}) 是带噪动作， (hat v_t) 是去噪速度场。官方 N1.7 资料确认 flow matching、AdaNorm 和 4 步推理，但没有独立论文重新给出完整损失推导；更细的数学定义仍来自 N1.X 技术谱系，不能假装是 N1.7 新提出的公式。

### 4. Relative EEF 与跨具身对齐

N1.7 把机器人与人类共有的末端执行器动作表示为相对当前位姿的增量，而不是绝对世界坐标目标：

$$
\Delta p_t=p_{t+1}-p_t,
\qquad
\Delta R_t=R_t^{-1}R_{t+1}.
$$

仓库认为这种共享相对坐标是人类视频迁移和跨具身泛化的关键。具体动作仍按 embodiment 配置：以 DROID 为例，EEF 使用 9D 的“XYZ + 6D rotation”相对表示，夹爪位置为绝对量，关节位置为相对量。也就是说，“统一”发生在可共享的动作语义层，并非强迫所有机器人拥有相同关节向量。[官方 DROID 配置说明](https://github.com/NVIDIA/Isaac-GR00T/blob/main/examples/DROID/README.md#data-format)

### 5. 预训练数据与后训练接口

4 月发布页给出精确的人类视频子集：20,854 小时、20 多个任务类别。7 月技术博客给出更宽的总口径：约 32,000 小时真实示范与人类第一视角数据，另有约 8,000 小时来自 BEHAVIOR、RoboCasa 和 simulated GR-1 的模拟 rollout/示范。两者可能分别对应“EgoScale 人类子集”和“总预训练混合”，但官方没有发布逐数据集对账表，不能直接相加或视为同一统计口径。[4 月发布页](https://huggingface.co/blog/nvidia/gr00t-n1-7#training-on-human-egocentric-video-data)；[7 月技术博客](https://developer.nvidia.com/blog/develop-humanoid-robot-policies-end-to-end-with-nvidia-isaac-gr00t/#get-started-with-gr00t-1-7)

模型卡另称训练数据共有 13 个数据集、21.6 million data points，采集与标注混合使用人、机器人、模拟和自动流程；但没有定义一个 data point 对应帧、时间步还是样本窗口，也没有列出全部 13 个数据集与配比。公开后训练 checkpoint 包括 DROID、LIBERO、SimplerEnv Bridge 和 Fractal。自定义机器人需将图像、状态、动作和语言转换为 LeRobot 格式，注册 modality/embodiment 配置后再微调。[官方模型卡“Training and Evaluation Datasets”](https://huggingface.co/nvidia/GR00T-N1.7-3B#training-and-evaluation-datasets)；[官方 checkpoint 列表](https://github.com/NVIDIA/Isaac-GR00T#model-checkpoints--embodiment-tags)

### 6. 推理与部署

官方部署基准固定为单相机、4 个去噪步，因而适合比较后端，不代表完整机器人系统的传感、网络、控制和安全延迟：

| 设备 | PyTorch Eager | TensorRT | 官方加速比 |
|---|---:|---:|---:|
| H100 80GB | 85.8 ms / 11.7 Hz | 27.9 ms / 35.9 Hz | 3.08× |
| L40 | 128.3 ms / 7.8 Hz | 38.4 ms / 26.0 Hz | 3.34× |
| AGX Thor | 144.9 ms / 6.9 Hz | 93.8 ms / 10.7 Hz | 1.54× |
| Orin | 342.8 ms / 2.9 Hz | 216.5 ms / 4.6 Hz | 1.58× |

H100、L40 和 Thor 可导出完整 VLM + 动作头流水线；Orin 因 TensorRT 10.3 不支持骨干引擎，只加速 DiT。部署还依赖受限访问的 Cosmos-Reason2-2B 骨干，使用者需在 Hugging Face 申请权限并认证。[官方部署基准](https://github.com/NVIDIA/Isaac-GR00T/blob/main/scripts/deployment/README.md#performance)

## 实验

### 1. SimplerEnv：平均提升与任务级退化并存

![N1.7 SimplerEnv 官方结果表](/images/literature-notes/gr00t-n17/key-results.png)

*图 2｜官方仓库当前 `main` 中的 SimplerEnv 默认评测结果。Bridge 与 Fractal 都是各自数据集后训练后的 checkpoint，而非同一个基础模型零样本测试；截图于 2026-08-18，本地保存未改动表内数字。[仓库原表](https://github.com/NVIDIA/Isaac-GR00T/blob/main/examples/SimplerEnv/README.md#benchmark-results)*

| 基准 | N1.6 平均成功率 | N1.7 平均成功率 | 绝对变化 |
|---|---:|---:|---:|
| Bridge / WidowX，7 任务 | 56.6% | 62.3% | +5.7 个百分点 |
| Fractal / Google Robot，6 任务 | 52.0% | 72.5% | +20.5 个百分点 |

平均数掩盖了明显异质性。Bridge 的 `stack_cube` 从 5% 升至 48%，但 `put_eggplant_in_basket` 从 89% 降至 53%，`put_eggplant_in_sink` 从 33% 降至 2%。Fractal 的最大提升来自 `open_drawer` 的 0%→65%，而 `place_in_closed_drawer` 仅 5%→7%。所以合理结论是“总平均改善、具体任务有大幅正负波动”，不是“全面优于 N1.6”。

7 月技术博客另写 DROID-F0 `+10%`、DROID-F6 `+61%`、SimplerEnv Bridge `+5%`、Fractal `+2%`，但未说明这些是相对比例还是百分点，也没有给出分母、试验次数和 checkpoint。它与当前仓库 Fractal 平均值的 +20.5 个百分点显然不是同一统计量，本文保留两套有日期的官方口径，不把它们强行合并。[技术博客“Improved benchmarks”](https://developer.nvidia.com/blog/develop-humanoid-robot-policies-end-to-end-with-nvidia-isaac-gr00t/#get-started-with-gr00t-1-7)

### 2. LIBERO：高成功率，但官方百分数与计数不完全一致

官方仓库报告四个专门后训练的 LIBERO suite，每项运行 200 次：Spatial 195/200、Goal 195/200、Object 197/200、10-Long 189/200，微调均为 20K steps、global batch size 640。[官方 LIBERO README](https://github.com/NVIDIA/Isaac-GR00T/blob/main/examples/LIBERO/README.md#libero-evaluation-benchmark-result)

README 同时印出的百分比分别是 97.65%、97.5%、98.45%、94.35%，其中三项与整数分数的直接除法不一致：195/200=97.5%、197/200=98.5%、189/200=94.5%。这可能是文档更新时分子与百分数未同步，或分母并非表面所示；在官方澄清前，原始计数比小数百分比更可审计。该表也没有 N1.6 或其他 VLA 的同协议基线，因而只能描述 N1.7 checkpoint 的水平，不能证明版本升级带来的因果增益。

### 3. DROID：零样本 open-loop 误差不是闭环任务成功

基础模型支持 DROID embodiment 的零样本推理。官方示例文档在三条 demo episode 的小样本上给出平均 MSE 约 0.0149、MAE 约 0.0753，H100 每步约 262 ms；微调 checkpoint 约 253 ms。[官方 DROID README](https://github.com/NVIDIA/Isaac-GR00T/blob/main/examples/DROID/README.md#1-standalone-inference-with-demo-data)

这是动作预测与数据集真值之间的 open-loop 误差，用于检查接口和数值是否正常；它没有让机器人执行任务，也没有测成功率、碰撞或误差积累。因此不能把低 MSE 叙述成“零样本真机成功”。

### 4. 真机与灵巧操作证据

4 月发布页称模型在 Unitree G1、Bimanual Manipulator YAM 与 AGIBot Genie 1 上覆盖 loco-manipulation、桌面操作和双臂灵巧任务，并展示 22-DoF 手的案例。模型卡则把真实评测概括为杂货装箱、未见物体和多机器人交接，但没有 N1.7 专属任务列表、试验次数、成功率、失败类型或基线。

模型卡引用“as defined in the White Paper”的 9 个 DexMimicGen、24 个 RoboCasa、24 个 Digital Cousin 和 GR-1 真机任务，但这些名称来自 N1 白皮书。没有 N1.7 数字时，不能把 N1 的成功率移植到 N1.7；本文只把这段视作评测范围声明，不当作实验证据。

## 主要发现

1. **最可核查的算法变化是表示与接口，而非单一新损失**：Cosmos/Qwen3-VL、relative EEF、40 步动作 horizon、32 层 flow-matching DiT 与完整部署栈都能由 checkpoint/代码交叉核对。
2. **人类视频规模显著扩大**：20,854 小时 EgoScale 是明确的人类子集；“约 32K 真实/人类 + 8K 模拟”是后续更宽口径。数据规模可确认，逐数据集配比和清洗流程不可确认。
3. **公开定量证据主要来自后训练 checkpoint**：SimplerEnv 与 LIBERO 的结果不能直接归为 3B 基础模型的零样本能力，也不能把数据、训练配方和骨干升级的贡献分开。
4. **平均提升不等于鲁棒提升**：Bridge 中存在 30 个百分点以上的任务退化，说明跨任务稳定性仍是关键问题。
5. **部署优化是发布的强项**：H100/L40 的全流水线 TensorRT 在固定条件下达到约 3× 加速；但边缘平台仍受骨干和 TensorRT 能力限制。
6. **资料本身是移动目标**：EA/GA、16/32 层默认配置、数据口径、许可证和基准小数均存在跨页面差异，任何结论都应绑定检索日期与具体 checkpoint。

## 结论

N1.7 提供了一条工程上连贯的路线：以 Cosmos-Reason2 承担视觉语言与任务分解，以 flow-matching DiT 生成连续动作，用 relative EEF 把人类/机器人数据映射到可共享空间，再通过 LeRobot、后训练、Policy API、ONNX/TensorRT 支持多具身部署。官方代码、权重与基准脚本使这条路线比只展示视频的版本更可检查。

但官方证据最多支持“版本实现完整、若干后训练模拟基准平均改善、推理后端显著加速”。没有 N1.7 独立论文、真机定量表和受控消融时，不能进一步断言 EgoScale 必然导致所有机器人技能提升，也不能把发布页关于长时推理、工厂可用或跨具身泛化的措辞等同于严格验证。

## 局限与适用边界

### 官方明确承认的局限

- 模型卡安全子卡明确说：N1.7 未经面向功能安全的关键任务测试，不适用于要求功能安全的 mission-critical 应用；用户必须自行加入 guardrail 和安全机制。[Safety & Security 子卡](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/SAFETY_and_SECURITY.md)
- 官方列出的风险包括动态环境、物体/家具变化、光照变化、客户环境集成以及部分机器人 embodiment 支持有限。[Explainability 子卡](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/EXPLAINABILITY.md)
- 仓库提醒微调受非确定性图像增强影响，不同运行可能有 5%–6% 波动；小幅基准差异可能落在训练方差内。[仓库 Training Tips](https://github.com/NVIDIA/Isaac-GR00T#training-tips)
- 基础 checkpoint 只对已登记的预训练 embodiment 支持零样本推理；新机器人通常需要数据映射、配置和后训练。

### 额外证据与复现风险

- **没有独立论文**：缺少专属损失定义、数据明细、训练计算、消融、统计不确定性和同行评审；N1 白皮书不能替代 N1.7 方法与结果。
- **后训练混杂**：Bridge、Fractal、LIBERO 的 checkpoint 使用不同数据与超参数，版本比较无法分离预训练、表示、微调和随机种子的贡献。
- **模拟到真实的外推有限**：公开的完整成功率表主要是模拟评测；真机展示缺少样本量与失败分布。
- **指标不统一**：open-loop MSE、模拟成功率、发布页相对增益和推理 Hz 回答的是不同问题，不能合成一个“总体能力分数”。
- **文档版本漂移**：模型卡仍写 EA 且残留 SigLIP2/T5 描述；发布页与 checkpoint 是 32 层 DiT，固定 tag、当前通用配置和兼容性说明却写 16 层。运行公开权重应以其 `config.json` 为准，方法比较则必须报告 commit 与实际加载配置。
- **数据透明度不足**：20,854 小时、约 32K+8K 小时、21.6M data points/13 datasets 没有统一对账，数据许可、去重、质量过滤与各 embodiment 比例未完整披露。
- **基准文档存在算术问题**：LIBERO 三项计数与打印百分数不一致；仓库 `main` 也会继续变化，结果应固定 commit 后再复现。
- **骨干访问限制**：代码和 GR00T 权重可见，但运行时依赖 gated 的 Cosmos-Reason2-2B；“开放”不等于无条件离线可运行。

### 许可证边界：官方资料目前互相冲突

这不是法律意见，但复现或商业部署前必须单独核实：

- Isaac-GR00T **代码仓库**标为 Apache-2.0，当前 README 和 7 月博客还称 N1.7 可商业使用；
- Hugging Face 模型卡正文称模型受 NVIDIA Open Model License 管理，并写“commercial/non-commercial use”；
- 但模型仓库实际随附的 [`LICENSE`](https://huggingface.co/nvidia/GR00T-N1.7-3B/blob/main/LICENSE) 第 3.3 节写明除 NVIDIA 外只可非商业使用，Explainability / Safety 子卡又链接 NSCL V1 非商业许可证。

因此不能仅凭博客或仓库 README 推断模型权重的最终商业授权。应确认下载时适用的许可证版本、代码与权重是否分别授权，并让 NVIDIA 或专业法律顾问书面澄清。

## 我的思考

我认为 N1.7 最值得研究的不是“把 VLM 换成更强模型”，而是 relative EEF 把数据规模问题改写成表示问题：只有人类和机器人动作在共享坐标中可比较，20K 小时人类视频才可能成为控制监督。下一步最关键的消融应固定 VLM 与机器人数据，分别比较 absolute EEF、relative EEF、只用机器人数据、加入 1k/4k/20k 小时人类数据，并在同一组真机任务上报告均值、置信区间和失败类型。

官方 SimplerEnv 表也提示，平均分会掩盖严重回退。比“平均提升多少”更有价值的版本门槛应包括：每任务最坏退化、跨随机种子方差、碰撞/安全停止率、未见物体与未见背景的分层结果，以及基础模型和后训练模型分开报告。

最后，这次阅读本身说明机器人基础模型需要 **可版本化证据**：固定 checkpoint 哈希、训练数据清单、不可变 benchmark manifest、精确许可证和模型卡应一起发布。否则软件持续更新虽然有利于工程，却会让“论文式结论”随 `main` 分支漂移，外部研究者很难知道复现的是哪个 N1.7。
