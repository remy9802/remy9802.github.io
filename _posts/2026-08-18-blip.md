## 核心结论

BLIP 的核心不是单独发明新的视觉骨干，而是把三种常被拆开的视觉—语言能力装进一个 **Multimodal Mixture of Encoder-Decoder（MED）**：用图文对比学习得到可检索的双塔表示，用跨模态匹配学习细粒度融合表示，再用因果语言建模生成文本。文本编码器和解码器共享大部分参数，仅保留不同的 self-attention，以兼顾双向理解和自回归生成。[原文 Figure 2、§3.1](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

第二个贡献 **CapFilt** 更接近数据工程：captioner 为网页图片补写描述，filter 同时清理原始网页文本和合成描述。14M 图像的受控消融显示，captioner 与 filter 合用时，COCO 图文检索 Recall@1 从 78.4/60.7 提至 80.6/63.1，COCO CIDEr 从 127.8 提至 129.7，NoCaps CIDEr 从 102.2 提至 105.1。这个对照比跨论文“SOTA”排名更能直接支持 BLIP 的主张。[原文 Table 1](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

## 研究背景

BLIP 之前的视觉—语言预训练大致分成三类架构：CLIP/ALIGN 式双塔擅长高效检索和开放词汇表示，UNITER/ALBEF 式 fusion encoder 擅长细粒度图文推理，encoder-decoder 则适合 caption 与开放生成。问题在于，一种架构通常只能覆盖其中一部分任务；将所有任务都改写为文本生成又可能牺牲检索和匹配能力。

数据侧也存在矛盾。网页 alt-text 规模大，却常包含模板文本、邻近网页内容或不完整描述；简单扩大数据量会同时扩大监督噪声。BLIP 因此提出两个相互关联的问题：

1. 能否让一组主要共享的参数分别表现为双塔编码器、跨模态融合编码器和条件文本解码器？
2. 能否让已经学到图文关系的模型反过来生成、筛选训练语料，以提升下一轮预训练？

## 研究问题

论文具体检验：

1. ITC、ITM 和 LM 能否在统一架构中互补，而不是相互干扰？
2. 文本 encoder 与 decoder 应共享哪些层，才能在参数效率和任务冲突之间取得平衡？
3. captioner 与 filter 各自贡献什么，合用是否优于单独使用？
4. 合成 caption 的“多样性”是否比低噪声的确定性生成更重要？
5. 从图像任务学到的表示能否零样本迁移到视频，而不额外做视频预训练？

## 方法与数据

### 1. MED：一套参数，三种运行方式

![BLIP 的 MED 架构与三个预训练目标](/images/literature-notes/blip/method-overview.png)

*图 1｜BLIP 将同一文本 Transformer 切换为 unimodal text encoder、image-grounded text encoder 和 image-grounded text decoder，分别优化 ITC、ITM 与 LM。相同颜色表示共享参数。来源：原论文 Figure 2，PMLR PDF 第 2 页。[原图](https://proceedings.mlr.press/v162/li22n/li22n.pdf)*

视觉侧是 ViT。输入图像先变成 patch tokens；文本侧从 BERT-base 初始化，并按任务切换注意力结构：

- **Unimodal encoder + ITC**：图像与文本各自编码，不发生 cross-attention；两个 `[CLS]` 表示进入共享空间，用图像到文本、文本到图像的对比损失拉近正配对、推远负配对。实现沿用 ALBEF 的 momentum encoder 与 soft targets，以减轻 batch 中“语义相近但被当成负例”的假负样本问题。
- **Image-grounded text encoder + ITM**：每个文本 block 加入对图像 token 的 cross-attention，并用 `[Encode]` 标记当前是理解任务；二分类头判断图文是否匹配。负例不是均匀随机抽取，而是从当前模型认为相似的样本中挖 hard negatives。
- **Image-grounded text decoder + LM**：把双向 self-attention 替换为 causal self-attention，以 `[Decode]` 开始，在图像条件下逐 token 预测 caption；训练使用 label smoothing 0.1。

总目标可概括为：

$$
\mathcal L_{\mathrm{BLIP}}
=\mathcal L_{\mathrm{ITC}}
+\mathcal L_{\mathrm{ITM}}
+\mathcal L_{\mathrm{LM}}.
$$

三次任务前向共享同一次视觉编码。文本 encoder 与 decoder 共享 token embedding、cross-attention 和 feed-forward network，但不共享 self-attention：前者需要双向上下文，后者必须满足因果约束。Table 3 表明，“除 self-attention 外全部共享”用 252M 参数达到 78.4/60.7 的 COCO 双向 Recall@1；完全不共享增至 361M 参数，却只有 78.3/60.5，说明适当共享同时减少参数并形成正迁移。[原文 §3.1、Table 3](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 2. CapFilt：先生成，再独立过滤

![BLIP 的 CapFilt 数据自举流程](/images/literature-notes/blip/capfilt-pipeline.png)

*图 2｜预训练 MED 分别在 COCO 上微调为 captioner 和 filter。captioner 为网页图像生成新描述；filter 独立判断原始与合成文本是否匹配图像；清洗后的语料用于重新预训练。来源：原论文 Figure 3，PMLR PDF 第 4 页。[原图](https://proceedings.mlr.press/v162/li22n/li22n.pdf)*

CapFilt 的步骤是：

1. 先在原始图文数据上预训练 MED；
2. 复制出两个模型，并分别在 COCO 人工标注数据上微调：captioner 只优化 LM，filter 优化 ITC/ITM；
3. 对每个网页图像，captioner 生成一个 synthetic caption；
4. filter 分别检查原始 web text 与 synthetic caption，将判为不匹配的 pair 删除；
5. 把保留下来的两类网页 pair 与人工标注 pair 合并，重新预训练最终模型。

captioner 和 filter 必须独立微调。若共享过多参数，生成器容易生产 filter 偏好的“安全”描述，形成确认偏差。Table 4 中独立方案的生成噪声率更高，却给出更强下游结果，说明“被过滤器容易接受”并不等于“为表示学习提供了更多信息”。[原文 §3.2、Table 4](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 3. 为什么采用 nucleus sampling

captioner 用 nucleus sampling，阈值 $p=0.9$。Table 2 中，beam search 生成文本的过滤噪声率为 19%，nucleus sampling 为 25%；但后者在检索和描述任务都更好，例如 COCO text retrieval Recall@1 为 80.6，而 beam 为 79.6。作者的解释是，随机采样带来的描述多样性比追求单个最大概率句子更有利于学习。[原文 §4.3、Table 2](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

需要注意，这里的“noise ratio”是 BLIP filter 自己的判定，不是独立人工事实核验；它支持模型内部的 diversity–agreement 权衡，不等同于测得真实错误率。

### 4. 数据与训练配置

基础数据约 14M 图像，来自 COCO、Visual Genome、Conceptual Captions 3M/12M 和 SBU；扩展设置再加入约 115M LAION 子集，合计约 129M 图像。ViT-B/16 与 ViT-L/16 分别从 ImageNet 预训练权重初始化，文本 Transformer 从 BERT-base 初始化。

论文报告预训练 20 epochs，batch size 为 2880（ViT-B）或 2400（ViT-L），AdamW weight decay 0.05；输入为 $224\times224$，下游微调通常增至 $384\times384$。训练使用两个 16-GPU 节点。论文开放代码与检查点，但不能仅凭这些信息重建 LAION 子集、网页文本状态和完整数据清洗结果。[原文 §4.1、Appendix A](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

## 实验

### 1. CapFilt 的受控消融

![BLIP 的 CapFilt 核心消融](/images/literature-notes/blip/key-results.png)

*图 3｜在 14M 与 129M 数据、ViT-B/L 两种视觉骨干上，captioner（C）和 filter（F）合用的结果最稳定；表格同时覆盖检索、COCO caption 与 NoCaps 零样本描述。来源：原论文 Table 1，PMLR PDF 第 5 页。[原表](https://proceedings.mlr.press/v162/li22n/li22n.pdf)*

14M、ViT-B 的同配置对照如下：

| 设置 | COCO TR@1 | COCO IR@1 | Flickr 零样本 TR@1 / IR@1 | COCO BLEU@4 / CIDEr | NoCaps CIDEr / SPICE |
|---|---:|---:|---:|---:|---:|
| 无 CapFilt | 78.4 | 60.7 | 93.9 / 82.1 | 38.0 / 127.8 | 102.2 / 13.9 |
| 仅 filter | 79.1 | 61.5 | 94.1 / 82.8 | 38.1 / 128.2 | 102.7 / 14.0 |
| 仅 captioner | 79.7 | 62.0 | 94.4 / 83.6 | 38.4 / 128.9 | 103.4 / 14.2 |
| captioner + filter | **80.6** | **63.1** | **94.8 / 84.9** | **38.6 / 129.7** | **105.1 / 14.4** |

附录 Table 12 用重复原语料将 seen texts 从 15.3M 增至 24.7M，结果没有改善；相同文本量下 CapFilt 明显更强。因此主增益不能仅解释为“训练步数或文本实例更多”。[原文 Appendix Table 12](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 2. 图文检索与图像描述

ViT-L、129M 的 BLIP 在 COCO image-to-text / text-to-image Recall@1 为 82.4 / 65.1，Flickr30K 为 97.4 / 87.6。与同为 14M 训练数据的 ALBEF 对照，BLIP 的 COCO 双向 Recall@1 平均提高约 2.7 个百分点，和摘要中的表述一致。[原文 Tables 5–6](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

图像描述方面，ViT-L、129M 在 COCO 达到 BLEU@4 40.4、CIDEr 136.7；NoCaps 达到 CIDEr 113.2、SPICE 14.8。不过 BLIP 并非所有指标都最高：使用约 1.8B 图像的 SimVLM 在 COCO CIDEr 报告 143.3，而 BLIP 更突出的证据是以更少图文数据兼顾理解与生成。[原文 Table 7](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 3. VQA、NLVR、VisDial

- 14M BLIP 在 VQAv2 test-dev / test-std 为 77.54 / 77.62，对应 ALBEF 为 75.84 / 76.04；test-std 提升约 1.6 个百分点。
- 129M BLIP 达到 78.24 / 78.17；ViT-L 版本为 78.25 / 78.32。
- NLVR2 并非全面领先：14M BLIP 的 test-P 为 82.30，低于表中 ALBEF 的 83.14。这个反例提醒我们，统一训练并不保证每项组合推理任务都改善。
- VisDial v1.0 报告 MRR 69.41、Recall@1 56.44。[原文 Tables 8–9](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 4. 零样本视频迁移

BLIP 先在对应的 COCO 图文检索或 VQA 任务上微调，再零样本迁移到目标视频数据集。每段视频均匀采样帧并拼接图像特征：检索使用 8 帧，VideoQA 使用 16 帧；没有视频预训练，也没有显式时间建模。在 MSRVTT retrieval 上 text-to-video Recall@1 为 43.3；在 MSRVTT-QA / MSVD-QA 上为 19.2 / 35.2。[原文 Tables 10–11](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

这些结果证明静态图文语义可迁移到视频基准，却不能证明模型学到了动作顺序、事件因果或长时动力学；8 帧拼接甚至没有利用帧序。

## 主要发现

1. **理解与生成可以共享主体，但注意力方向不能机械统一。** 双向 encoder 与因果 decoder 各保留 self-attention，其余层共享，优于更大的完全分离方案。
2. **BLIP 的“bootstrapping”主要发生在数据层。** 模型先充当 captioner/filter，再用改写后的语料训练新模型；它不是强化学习或在线自我改进。
3. **生成多样性比 filter 接受率更有解释力。** nucleus sampling 虽被 filter 拒绝得更多，下游效果反而更好。
4. **内部消融比跨模型榜单更可信。** Table 1、2、3、12 分别控制 CapFilt、解码方式、参数共享和训练量；跨论文比较则混合数据、骨干和算力。
5. **图像表示的零样本视频迁移有明显边界。** 它体现语义复用，不等于具备 temporal world model。

## 结论

BLIP 证明了一个视觉—语言模型可以在同一预训练阶段联合学习全局对齐、细粒度匹配和条件生成；CapFilt 则把模型能力反馈到数据构造中，缓解网页文本噪声。它成为 BLIP-2 的直接方法基础：后者继承 ITC/ITM/生成目标，却把“统一模型”改成“冻结强模型 + 可训练桥接器”。[原文 Conclusion](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

## 局限与适用边界

### 作者明确提出的后续方向

原文没有独立 Limitations 节，但在结论中提出三项未完成工作：多轮执行 CapFilt；每张图生成多个 synthetic captions；使用多个 captioner/filter ensemble。这说明论文只验证了一轮、单描述、单模型的数据自举。[原文 Conclusion](https://proceedings.mlr.press/v162/li22n/li22n.pdf)

### 额外识别的局限

- CapFilt 的 captioner 与 filter 都由相近数据和模型初始化，可能共同放大同一类语言偏见、遗漏与幻觉；“独立微调”不能提供真正独立的事实审计。
- filter 只判断图文匹配，不检查文本是否完整、是否包含不可见推断，也不能保证合成描述的社会与事实可靠性。
- 129M 实验依赖 LAION 子集和特定清洗状态；官方代码与权重不足以完整复现当时网页数据。
- 跨模型表格没有严格配平训练图像数、计算量、视觉初始化和分辨率；不能把所有差值都因果归给 MED 或 CapFilt。
- 论文大多报告单点指标，没有随机种子、方差或置信区间。
- 下游仍需任务特定微调、输入格式和输出头；“unified”指共享预训练主体，不等于一个 checkpoint 无修改覆盖所有任务。
- VQA 虽以生成式模型训练，但论文推理时对 3,128 个候选答案排序；它不是完全无约束的开放文本生成。
- 视频实验没有显式时间建模，因此不适合据此推断动作理解或长期视频推理能力。
- 官方仓库已经归档，旧依赖和权重下载路径的长期可维护性需要另行检查。

## 我的思考

BLIP 最值得保留的思想是把“模型结构统一”和“数据质量提升”放进同一因果链。MED 让同一表示同时接受对比、融合和生成信号；CapFilt 再让生成能力改变下一轮监督分布。这比简单增加参数更接近后来基础模型的实际 recipe。

但 CapFilt 也提出一个至今没有消失的问题：当模型既产生训练标签，又负责判定标签质量时，怎样避免系统只强化自己已经容易表达和识别的概念？更可靠的后续方案应加入来源多样的教师、人工抽样审计、事实与安全过滤，以及按概念/地区/语言分层的覆盖率报告，而不只比较平均下游分数。
