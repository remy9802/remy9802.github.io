## 核心结论

SigLIP 保留 CLIP 的图像—文本双塔，只把 batch 级双向 softmax 改为每个图文组合独立判断“匹配/不匹配”的 sigmoid 损失。这个改动让损失可以按设备分块计算，避免一次物化全局相似度矩阵；在小 batch 下通常优于 softmax，并且实验显示收益在约 32k batch 已基本饱和，而不是“batch 越大越好”。[原文 Figures 1–2](https://arxiv.org/pdf/2303.15343)

它改善的是目标函数耦合、分布式通信和峰值显存，并没有消除所有图文组合的二次计算量。论文最强公开结果还同时受 WebLI 数据、训练样本数、模型规模和优化设置影响，不能把相对 CLIP 的全部提升只归因于 sigmoid 损失。

## 研究背景

CLIP 以一个 batch 内的完整图文相似度矩阵进行双向 softmax：每幅图像必须在全部文本中选出正确项，每段文本也必须在全部图像中选出正确项。这种 InfoNCE 式目标有效，却把损失定义与 batch 绑定。多设备训练时，通常需要汇集全局 embedding，并处理 (B\times B) 相似度矩阵；因此扩大负样本数量会增加通信、显存和实现复杂度。

SigLIP 的问题不是重新设计视觉编码器，而是追问：图文匹配能否直接写成许多独立二分类任务？如果每一对的损失彼此独立，设备之间就可以循环交换文本分块并逐块累积损失，不必同时持有全局矩阵。[原文 Introduction 与 §3](https://arxiv.org/pdf/2303.15343)

## 研究问题

论文围绕四个问题展开：

1. pairwise sigmoid 能否在相同图文双塔上达到或超过 softmax 对比损失？
2. 独立 pair 损失能否减少全局 all-gather 与峰值 loss-matrix 内存？
3. 性能如何随 batch 从数千扩展到一百万，超大 batch 是否仍有持续收益？
4. 正负样本比例、bias/temperature 初始化、优化器与数据噪声会怎样影响训练？

## 方法与数据

![SigLIP 分块分布式损失计算](/images/literature-notes/siglip/method-overview.png)

*图 1｜三个设备先计算本地正负图文组合，再循环置换文本 embedding；任一时刻只需物化一个设备分块的相似度矩阵。来源：原论文 Figure 1，arXiv PDF 第 3 页。[原图](https://arxiv.org/pdf/2303.15343)*

### 1. 双塔表示保持不变

图像编码器 (f) 与文本编码器 (g) 分别输出归一化向量：

$$
x_i=\frac{f(I_i)}{\lVert f(I_i)\rVert},\qquad
y_j=\frac{g(T_j)}{\lVert g(T_j)\rVert}.
$$

图文相似度写为：

$$
s_{ij}=t\,x_i^\top y_j+b,\qquad t=\exp(t').
$$

其中匹配对标签 (z_{ij}=+1)，其他组合 (z_{ij}=-1)。SigLIP 损失为：

$$
\mathcal L_{\mathrm{sigmoid}}
=-\frac{1}{B}\sum_{i=1}^{B}\sum_{j=1}^{B}
\log\sigma(z_{ij}s_{ij}).
$$

每个 pair 不再参与一条跨 batch 的归一化分母。论文初始化 (t'=\log 10)、(b=-10)，用负 bias 抵消一个 batch 中 (B) 个正对与 (B^2-B) 个负对之间的极端不平衡；消融显示该初始化对早期训练很重要。[原文 §3.2、Table 4](https://arxiv.org/pdf/2303.15343)

### 2. 分块分布式实现

每个设备保留本地图像 embedding，将文本 embedding 在设备间循环置换。第 (k) 轮只计算本地图像与当前文本分块的 (b\times b) pair loss，累加后再传递文本。这样单设备不必一次保存 (B\times B) 的全局 loss matrix，也不要求所有 embedding 同时 all-gather。

这个实现降低的是峰值内存和全局同步压力。所有正负组合仍需参与目标，因此 pair 计算总量仍近似 (O(B^2))；不能把它表述为线性复杂度。[原文 Figure 1 与 §3.3](https://arxiv.org/pdf/2303.15343)

### 3. 数据、模型与训练

- 主实验使用 WebLI 英文子集；多语言 mSigLIP 覆盖 100 多种语言。
- 图像塔与文本塔主要为 ViT；基础实验使用 ViT-B/16 与文本 B，224×224 输入。
- batch-size 对照统一固定“见过的样本数”，避免大 batch 仅因处理更多样本占优：SigLIP 主扫描约 9B seen examples，SigLiT 扫描约 18B，多语言设置约 30B。
- 发布模型常用 batch 32k、总计约 40B examples；大 batch 时将 Adafactor 的 \(\beta_2\) 从 0.999 调低至约 0.95，以缓解 gradient spikes。[原文 §4 与 Appendix](https://arxiv.org/pdf/2303.15343)

## 实验

### Batch size 并非越大越好

![SigLIP 的 batch-size 扫描](/images/literature-notes/siglip/key-results.png)

*图 2｜左、中分别是 SigLiT 与 SigLIP 的 ImageNet 零样本结果；sigmoid 在小 batch 更强，两种损失约在 32k 附近饱和。右图显示多语言检索在继续增大 batch 后反而下降。来源：原论文 Figure 2，arXiv PDF 第 4 页。[原图](https://arxiv.org/pdf/2303.15343)*

在控制 seen examples 后，sigmoid 在低于约 16k 的 batch 区间明显优于 softmax；两者到约 32k 后趋于饱和，继续放大常常没有收益。mSigLIP 在 Crossmodal-3600 的 text-to-image Recall@1 随 batch 32k、65k、131k、245k 约为 34.9、34.4、33.6、32.7，构成“超大 batch 可能退化”的直接反例。[原文 Figure 2、Table 2](https://arxiv.org/pdf/2303.15343)

### 有限算力实验

在冻结图像塔的 SigLiT 设置中，B/8 图像塔配文本 L、4 个 TPUv4、约一天训练达到 79.7% ImageNet 零样本准确率；g/14 配文本 L、4 个 TPUv4、约两天达到 84.5%。从头训练的 SigLIP B/16+B 使用 32 个 TPUv4，训练两天和五天分别达到 72.1% 与 73.4%。这些结果支持方法在较少设备下可训练，但不同模型初始化与数据设置不能横向视作同一控制实验。[原文 Table 1](https://arxiv.org/pdf/2303.15343)

### 公开模型比较

论文 v4 报告 SigLIP B/16 在 ImageNet 零样本为 76.2%，COCO image-to-text / text-to-image Recall@1 为 64.4 / 47.2；表中的 CLIP B 对应 68.3%、52.4 / 33.1。SigLIP L 与 So400m 进一步达到 80.5% 和 83.2% ImageNet 零样本准确率。[原文 Table 3](https://arxiv.org/pdf/2303.15343)

这张表混合了不同数据、seen examples、模型规模与训练配方，应作为“公开模型总体效果”而非损失函数的纯因果消融。更可靠的 loss 结论来自相同设置下的 batch 扫描。

### 初始化、负样本和噪声

同一消融中，(b=-10,t'=\log10) 得分 63.0；不使用 bias 为 62.0；将 bias 设为 0、温度从 1 开始则降至 53.7。随机删除负样本会损害性能，只保留最容易负例几乎失败，而较难负例更有信息；论文并未因此给出一个已解决的 hard-negative mining 配方。[原文 Figures 4–7、Table 4](https://arxiv.org/pdf/2303.15343)

## 主要发现

1. **损失可以从 batch 分类改写为独立 pair 分类。** 双塔架构与余弦相似度不变，核心变化是 sigmoid、bias 和分块执行。
2. **小 batch 是 SigLIP 最明确的优势区间。** 它不依赖超大 batch 才达到较好性能，约 32k 后收益快速饱和。
3. **系统效率不等于计算复杂度消失。** chunking 避免全局矩阵常驻显存，却仍要评价大量图文组合。
4. **负例数量不是唯一决定因素。** 负例难度、初始化和优化稳定性与 batch 大小同样关键。
5. **公开模型提升是完整配方的结果。** WebLI、40B examples、模型扩展与优化设置共同作用，不能用一张跨模型表只证明 loss 优越。

## 结论

作者认为，pairwise sigmoid 是图文预训练中比 batch-softmax 更简单、易扩展的替代目标：它在小 batch 下表现更好，允许按 pair 分块执行，并证明一百万 batch 并非必要。论文建议将约 32k 视作更合理的规模，而不是继续用硬件堆高全局 batch。[原文 Conclusion](https://arxiv.org/pdf/2303.15343)

## 局限与适用边界

### 论文直接呈现的边界

- 超大 batch 的收益很快饱和，甚至出现退化；一百万 batch 是压力测试，不是推荐默认值。
- 所有 off-diagonal 图文组合仍默认作为负例，其中可能包含真实语义相关对。
- 负样本选择影响显著，但论文没有解决通用 hard-negative mining。
- 大 batch 训练出现 gradient spikes，需要修改优化器二阶矩设置。
- 论文没有独立的 Limitations 章节，部分边界分散在实验和结论中。

### 额外识别的局限

- WebLI 与 40B-example 训练难以被外部完整复现；官方代码并不等于开放原始数据和全部基础设施。
- 分块实现降低内存和通信，不改变所有 pair 组合带来的二次计算规模。
- Table 3 的跨模型基线并未严格配平数据、训练样本和算力，因此不能把全部差异归因于 sigmoid。
- 评价主要是整图分类和检索；原始 SigLIP 没有直接解决区域定位、稠密预测、OCR 和文档结构。
- 多语言只覆盖有限评价集，且互联网数据的语言、地域和群体偏差没有得到系统解决。

## 我的思考

SigLIP 最值得学习的不是把 `softmax` 换成 `sigmoid` 这一行代码，而是把目标函数、分布式系统和实验设计放在同一个问题里。它用固定 seen examples 的 batch 扫描证明：扩大硬件并不会自动扩大有效监督，很多“规模收益”其实在较早阶段已经饱和。

这也解释了后续 SigLIP 2 的方向。SigLIP 已经把全局图文对齐做得更易训练，但仍只产生整图级表征；下一步必须用定位 decoder、自蒸馏和 masked prediction，把视觉塔从全局检索器扩展为能服务 OCR、区域定位和稠密视觉任务的编码器。
