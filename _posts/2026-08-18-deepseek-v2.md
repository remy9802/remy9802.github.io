## 核心结论

DeepSeek-V2 有 236B 总参数，但每个 token 只激活约 21B。容量与计算之所以能解耦，来自两项互补设计：Multi-head Latent Attention（MLA）把各层历史 key/value 联合压入低维 latent，缓解长序列和大 batch 生成的内存瓶颈；DeepSeekMoE 把 FFN 切成更多小专家，并分离共享专家与路由专家，降低每 token 激活量。一个优化的是“保存多少历史状态”，另一个优化的是“执行多少参数”。

论文在同一 H800 集群、每 1T token 的口径下报告：DeepSeek 67B 需 300.6K GPU-hours，DeepSeek-V2 需 172.8K，减少 42.5%。该数字不是 8.1T 预训练的完整账单；它也不包含研究试验、失败运行、数据处理和后训练。部署端的 5.76 倍生成吞吐，则同时使用 MLA、FP8 权重、平均 6-bit KV cache、8×H800 节点和线上请求分布，不能单独归因 MLA，也不能迁移成所有硬件的固定倍数。

能力上，V2 相对 DeepSeek 67B 的数学、代码和综合知识大幅提高，但 HellaSwag 等任务仍有回退。RL 进一步改善 HumanEval、LiveCodeBench 和开放式偏好评测，却使 MMLU、BBH、C-Eval 等略降，构成清晰的 alignment tax 证据。

## 研究背景

密集 Transformer 扩大参数量会同时增加每 token FLOPs；传统 MHA 又必须在自回归生成时为每层、每个历史 token 保存所有 head 的 key/value。模型越大、上下文越长、并发越高，参数计算与 KV cache 就越容易分别成为训练和服务瓶颈。MQA/GQA 能减少 KV head 数，却可能牺牲注意力表达能力；普通 MoE 能稀疏激活参数，却会带来专家冗余、负载塌缩和跨设备通信。

DeepSeek-V2 的目标不是只减少参数，而是同时改善三种资源：用低秩 latent 降 KV cache，用细粒度专家降激活计算，用设备约束与辅助损失控制 MoE 通信。这条路线承接 [DeepSeek LLM](/posts/deepseek-llm/) 的 67B 密集基线，并为 V3 的更大稀疏模型提供骨架。

## 研究问题

1. 能否在不退化到 MQA/GQA 表达能力的情况下，大幅缩小自回归推理的 KV cache？
2. 细粒度路由专家和共享专家能否让总容量扩大到 236B，而每 token 只激活约 21B？
3. 如何限制专家路由跨设备通信，并避免专家负载塌缩？
4. 架构节省能否在真实 H800 训练和服务中转化为 GPU-hours、吞吐和上下文长度收益？
5. SFT 与 GRPO 能否把基座能力转成数学、代码、帮助性和安全偏好，而不造成明显能力税？

## 方法与数据

![DeepSeek-V2 总体架构](/images/literature-notes/deepseek-v2/architecture.png)

*图 1｜DeepSeek-V2 的两条主线：MLA 把 K/V 投影到共享 latent 并单独承载 RoPE；DeepSeekMoE 将共享专家与被 top-k 选中的细粒度路由专家相加。来源：原论文 Figure 2，PDF 第 5 页。[原论文 PDF](https://arxiv.org/pdf/2405.04434#page=5)*

### 1. Multi-head Latent Attention（MLA）

MHA 每层每 token 需缓存约 \(2n_h d_h\) 个 K/V 元素。MLA 先把输入 \(h_t\) 下投影为联合 KV latent，再上投影成各 head 的内容 key/value：

$$
c_t^{KV}=W^{DKV}h_t,\qquad
k_t^C=W^{UK}c_t^{KV},\qquad
v_t^C=W^{UV}c_t^{KV}.
$$

生成时只需缓存 \(c_t^{KV}\)，而 \(W^{UK}\) 可吸收到 query 投影、\(W^{UV}\) 可吸收到输出投影。为减训练激活，query 也经低秩压缩：

$$
c_t^Q=W^{DQ}h_t,\qquad q_t^C=W^{UQ}c_t^Q.
$$

直接对压缩内容施加 RoPE 会使位置矩阵夹在投影之间，破坏权重吸收。MLA 因此把位置通道解耦：

$$
q_{t,i}=[q_{t,i}^{C};q_{t,i}^{R}],\qquad
k_{t,i}=[k_{t,i}^{C};k_t^{R}],
$$

其中 \(q^R,k^R\) 单独经过 RoPE，共享的 \(k_t^R\) 也被缓存。于是每层每 token 的缓存规模为

$$
(d_c+d_h^R)l,
$$

论文配置 \(d_c=4d_h\)、\(d_h^R=d_h/2\)，元素数相当于只有 2.25 组的 GQA。附录的小模型消融显示 MLA 的 loss/下游分数优于其 MHA、GQA、MQA 对照，但这不是所有架构和规模上的普适排序。[原论文 §2.1、Appendix D](https://arxiv.org/pdf/2405.04434#page=6)

### 2. DeepSeekMoE

对第 \(t\) 个 token，MoE 输出可写为共享专家与 top-\(K_r\) 路由专家之和：

$$
h'_t=u_t+
\sum_{i=1}^{N_s}\operatorname{FFN}^{(s)}_i(u_t)
+\sum_{i=1}^{N_r}g_{i,t}\operatorname{FFN}^{(r)}_i(u_t),
$$

$$
s_{i,t}=\operatorname{Softmax}_i(u_t^\top e_i),\qquad
g_{i,t}=s_{i,t}\,\mathbf 1\!\left[i\in\operatorname{TopK}(s_{:,t},K_r)\right].
$$

“细粒度”意味着把同等 FFN 容量切成更多小专家，使组合更灵活；“共享专家”持续处理共通知识，避免每个路由专家重复学习。主模型 60 层、hidden size 5,120；除第一层 FFN 外均为 MoE，每层有 **2 个共享专家、160 个路由专家、激活 6 个路由专家**，单专家 intermediate size 1,536。模型总参数 236B、激活参数约 21B。[原论文 §2.2、Table 2](https://arxiv.org/pdf/2405.04434#page=9)

路由先选 affinity 最高的至多 \(M=3\) 个设备，再只在这些设备上的专家做 top-k，限制一个 token 的通信扇出。训练仍加入三类辅助损失：expert-level、device-level 和 communication balance；训练时容量超限会 token dropping，评测时不丢 token。这里的效率来自“结构 + 路由 + 系统”的整体，而非单独稀疏参数量。

### 3. 模型、数据与预训练

- **数据**：约 8.1T token，中英文为主；论文称中文 token 数比英文约多 12%，并加强质量过滤、数据混合及对争议内容的过滤；100K 规模 BBPE tokenizer。
- **架构**：60 层，hidden 5,120；128 个 attention heads，每 head 128 维；MLA 的 KV 压缩维 512、query 压缩维 1,536、解耦 RoPE 每 head 64 维。
- **上下文**：预训练 4K。完成预训练后用 YaRN 做 1,000 step、32K 序列继续训练（batch 576），目标支持 128K；长上下文核心证据主要是 Needle-in-a-Haystack。
- **优化**：AdamW，\(\beta_1=0.9,\beta_2=0.95\)，weight decay 0.1；warm-up 2,000 step，峰值学习率 \(2.4\times10^{-4}\)，在 60% 与 90% 训练进度阶梯衰减；global batch 在前 225B token 从 2,304 逐步升到 9,216，之后保持 9,216。
- **系统**：内部 HAI-LLM；16-way zero-bubble pipeline parallel、8-way expert parallel、ZeRO-1，不使用 tensor parallel。论文说明在 H800 集群训练，但没有报告完整训练使用的 H800 数量。

### 4. SFT 与 GRPO

SFT 使用约 1.5M 指令实例（1.2M 帮助性、0.3M 安全），2 epochs，学习率 \(5\times10^{-6}\)。随后采用两阶段 RL：先以数学/代码 reasoning reward model 强化推理，再组合 helpful、safety 和 rule reward 做人类偏好对齐。

GRPO 对每个问题 \(q\) 从旧策略采样一组 \(G\) 个回答，以组内标准化奖励作为优势而不训练同规模 critic：

$$
A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}
{\operatorname{std}(r_1,\ldots,r_G)}.
$$

其目标沿用 PPO 式概率比裁剪，并加参考策略 KL：

$$
J_{\mathrm{GRPO}}=\mathbb E\left[
\frac1G\sum_i \min(\rho_iA_i,
\operatorname{clip}(\rho_i,1-\epsilon,1+\epsilon)A_i)
-\beta D_{KL}(\pi_\theta\|\pi_{ref})\right].
$$

不训练 value model 确实少了一个同量级网络，但采样多个长回答、reward inference 和分布式 rollout 仍有显著成本；论文没有给出 GRPO 与 PPO 在 V2 全尺寸上的等效果 GPU-hour 对照，因此不能把“省 critic”直接换算为固定成本比例。[原论文 §4.2](https://arxiv.org/pdf/2405.04434#page=16)

## 实验

![DeepSeek-V2 的性能—成本—吞吐比较](/images/literature-notes/deepseek-v2/efficiency-comparison.png)

*图 2｜论文摘要图把能力、每 1T token 训练成本和部署吞吐放在一起。三块采用不同协议：benchmark 平均分、同一 H800 集群的 GPU-hours，以及 8×H800 上按线上请求分布测得的 token/s，不能将三者视为同一个受控实验。来源：原论文 Figure 1，PDF 第 1 页。[原论文 PDF](https://arxiv.org/pdf/2405.04434#page=1)*

### 1. 基座能力

与 DeepSeek 67B 相比，V2 的 MMLU 为 78.5 vs. 71.3，MATH 43.6 vs. 18.7，HumanEval 48.8 vs. 45.1；但 HellaSwag 为 84.2 vs. 86.3。与 LLaMA 3 70B 相比，V2 的 MMLU 78.5 vs. 78.9、MATH 43.6 vs. 42.2。最稳妥的结论是 V2 在显著降低激活计算的同时达到同代 70B 密集模型的整体区间，并在数学/中文上突出，而不是在每项任务上领先。[原论文 Table 2](https://arxiv.org/pdf/2405.04434#page=14)

MLA 和 DeepSeekMoE 的附录消融主要使用较小规模模型，支持设计选择，却不能完全隔离 236B 最终模型中的贡献；后者同时改变数据、参数、优化和训练时长。

### 2. 训练与推理效率

在同一 H800 集群、**每 1T token** 口径下：

| 模型 | GPU-hours / 1T token | 相对 DeepSeek 67B |
|---|---:|---:|
| DeepSeek 67B | 300.6K | 100% |
| DeepSeek-V2 | 172.8K | 57.5% |

即节省 42.5%。若机械乘以 8.1 会忽略训练 batch、上下文、系统状态与统计口径变化，论文也没有如此给出总账单，因此本文不外推“全训练成本”。

部署时先把权重转为 FP8、把 KV cache 压至平均 6 bit；在单节点 8×H800 和真实线上 prompt/generation 长度分布下，生成吞吐超过 50K token/s，是 DeepSeek 67B 最大吞吐的 5.76 倍，prompt 处理超过 100K token/s。这是一个特定服务配置的系统结果，包含量化、batch 容量、内核和 MLA 联合收益。[原论文 §3.2.3](https://arxiv.org/pdf/2405.04434#page=16)

### 3. 长上下文

YaRN 扩展后的模型在 Needle-in-a-Haystack 上能到 128K。该测试主要检查能否在长序列中找回显式插入字符串，不充分覆盖长文推理、多跳整合、位置偏差、有效上下文利用率或 128K 服务吞吐；“支持 128K”应理解为位置扩展和检索测试通过，而非所有 128K 任务稳定。

### 4. 对齐与 alignment tax

同一表格中，RL 相比 SFT：HumanEval 76.8→81.1、LiveCodeBench 28.7→32.5；但 MMLU 78.4→77.8、BBH 81.3→79.7、C-Eval 80.9→78.0。开放偏好评测则 MT-Bench 8.62→8.97、AlpacaEval 2.0 length-controlled win rate 30.0→38.9。[原论文 Tables 3–4](https://arxiv.org/pdf/2405.04434#page=18)

这些结果支持 RL 改善代码和对话偏好，也显示部分知识/选择题能力回退。MT-Bench、AlpacaEval、AlignBench 使用模型裁判，可能受长度、文风与裁判模型偏好影响，不能替代人工盲评或真实任务成功率。

## 主要发现

1. **MLA 直接打击 KV cache，而不是只减少 KV heads。** 联合低秩 latent 保留多头上投影空间，解耦 RoPE 则维持权重吸收。
2. **DeepSeekMoE 将总容量与激活计算解耦。** 236B 总参数并不等于每 token 执行 236B；每 token 激活约 21B，但仍需存储和通信整个专家集合。
3. **效率是系统共同产物。** 训练节省依赖稀疏计算与 HAI-LLM，部署吞吐依赖 MLA、FP8、6-bit KV 和请求分布；任何单组件因果归因都过强。
4. **GRPO 用组内相对奖励替代 critic。** 这使超大模型 RL 更可操作，也成为后续 DeepSeek-R1 的核心算法接口。
5. **RL 收益与能力税并存。** 代码/对话偏好提高，并不保证 MMLU、BBH、C-Eval 同步提高。

## 局限与适用边界

### 作者明确报告的局限

- 知识静态，时效问题需外部检索；
- 仍有幻觉和非事实回答；
- 主要覆盖中文/英文，其他语言不足；
- 仅处理文本，未扩展到视觉等多模态；
- RL 中观察到 alignment tax，作者提出在线/离线 RL 的初步思路，但未进行全面比较。[原论文 §5](https://arxiv.org/pdf/2405.04434#page=21)

### 额外证据边界

- **成本范围窄**：42.5% 是每 1T token、同一 H800 集群对 DeepSeek 67B 的比较，不是总研发成本，也不包含试错和数据。
- **吞吐是组合结果**：5.76 倍同时改变权重精度、KV 精度和可服务 batch，不能只归因于 MLA。
- **全尺寸因果消融不足**：主要结构消融在较小模型上；最终 236B 模型的性能由数据、容量和架构共同决定。
- **训练/推理不完全同分布**：训练会 token dropping，评测不丢；极端负载和 OOD 路由的稳定性未充分报告。
- **长上下文证据有限**：NIAH 不能代表长文复杂推理；没有 128K 全套下游评测与服务成本曲线。
- **开放复现有限**：无完整预训练/GRPO/HAI-LLM 代码、语料与总训练账单。
- **评价风险**：开放式结果依赖 LLM judge，标准 benchmark 无种子与置信区间，数据污染无法外部审计。

## 路线关系

[DeepSeek LLM](/posts/deepseek-llm/) 提供 67B 密集基线和缩放方法；DeepSeek-V2 把核心矛盾转为“总容量、激活 FLOPs、KV cache 能否分别控制”。[DeepSeek-V3](/posts/deepseek-v3/) 沿用 MLA 和 DeepSeekMoE，进一步以 auxiliary-loss-free 路由、MTP、FP8 和 DualPipe 扩到 671B/37B-active；[DeepSeek-R1](/posts/deepseek-r1/) 则沿用 V3 Base 和 GRPO，把稀疏基座变成 reasoning model。因此 V2 是 DeepSeek 架构与后训练两条主线真正汇合的中点。

## 我的思考

MLA 最有价值的地方，是把“注意力表达空间”与“必须缓存的状态空间”分开；MoE 则把“知识容量”与“每 token 计算空间”分开。两者具有同一种设计哲学：用可学习的压缩/路由维持能力，用系统约束兑现效率。评价类似模型时，应分别报告总参数、激活参数、训练 FLOPs、KV bytes/token、batch 下吞吐和延迟，单独一个“参数量”已经失真。

后续最需要的是端到端开放证据：同精度、同 batch、同请求分布的 MLA/GQA 服务对照；全尺寸 MoE 路由消融；以及包含数据、失败试验和后训练的生命周期计算账单。只有这些补齐后，才能从“论文范围内经济”走向“可复现的总拥有成本”。

## 结论

DeepSeek-V2 证明了 MLA + 细粒度 MoE 是一条可在大规模训练与部署中兑现的工程路线，并用 GRPO 为后续 reasoning RL 建立接口。它的贡献真实且具体，但数字必须带口径：236B 是总容量、21B 是激活量，42.5% 是每 1T token 对照，5.76 倍是特定量化和硬件服务栈。把这些边界保留，才能准确理解 V2 的意义。
