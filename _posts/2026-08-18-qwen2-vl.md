## 核心结论

Qwen2-VL 用 Naive Dynamic Resolution 让视觉 token 数随图像尺寸变化，并以 M-RoPE 统一文本、图像和视频的时间-高度-宽度位置。它显著改善 OCR、文档和视频能力，但 MMMU 等综合推理仍落后于同期闭源模型，说明“看清”与“推理”是两个不同瓶颈。

## 研究背景

第一代 VLM 把所有图片缩放到固定方形分辨率，计算预算稳定，却会压扁长图、缩小文档小字，并让不同信息密度的图像使用相同 token 数。视频通常被当成若干独立图片，语言模型的一维位置编码也难同时表达“第几帧、图中第几行和第几列”。随着 OCR、长文档、视频和 GUI 成为核心任务，固定 448×448 输入已经成为明显瓶颈。

Qwen2-VL 的研究位置是把视觉输入从固定张量变成可变长度序列，并统一静态图像与视频的时空位置表示。相比第一代，它不只是扩大训练规模，而是重新设计“像素如何占用上下文”和“二维/时间坐标如何进入 LLM”这两个基础接口。

## 研究问题

固定尺寸会压缩高分辨率文档、拉伸极端长宽比图像，也难自然扩展到不同长度的视频。Qwen2-VL 研究怎样取消预定分辨率、让图像与视频共享视觉编码流程，并在同一 LLM 内保留二维几何和时间顺序。

## 方法与数据

![Qwen2-VL 动态分辨率视觉序列](/images/literature-notes/qwen2-vl/method-overview.png)

*图 1｜不同长宽比、分辨率的图像和不同时长的视频被编码为可变数量视觉 token，再与文本一起进入 Qwen2 解码器；这保留原生几何，但计算量随视觉 token 数变化。来源：原论文图 2。*

前向计算包含五步：按原比例把图像切为 14×14 patch；ViT 用 2D-RoPE 编码网格；2×2 patch merger 把四个视觉向量合为一个 LLM token；M-RoPE 为每个 token 分配时间/高度/宽度位置；视觉序列与文本序列拼接后由 Qwen2 causal decoder 生成答案或动作。视频只在视觉前端多一个深度为 2 的 3D 卷积与采样过程，后续接口与图像统一。

### 架构与视觉 token

2B、7B、72B 三个版本共享约 675M 参数 ViT，只更换 Qwen2 LLM，因此视觉前端计算基本固定。Naive Dynamic Resolution 移除 ViT 固定绝对位置嵌入，改用 2D-RoPE；图像保留原长宽比并产生可变数量 patch，再由两层 MLP 把相邻 2×2 patch 合并为一个 LLM token。例如 224×224、patch size 14 的图像合并后为 64 个视觉 token，再加起止标记共 66 个。

M-RoPE 把语言模型旋转位置通道拆为时间、高度、宽度三组。纯文本三组位置 ID 相同；图像的时间 ID 固定、空间 ID 沿二维网格变化；视频再让时间 ID 随帧推进。不同模态拼接时，后一模态从前一模态最大位置继续编号。这一设计既保留二维/时间结构，也让长图像和视频的最大位置值低于简单一维展开。

### 统一图像与视频

视频以 2 FPS 采样，使用深度为 2 的 3D convolution 把相邻两帧组成 tube；静态图像复制为两帧后走相同路径。训练时动态降低视频帧分辨率，把单视频视觉 token 限制在 16,384。这个上限是算力折中，不是无损读取：Video-MME 最多只取 768 帧，长达一小时的视频必然被稀疏采样。

### 训练

第一阶段约 600B token，主要训练图文对齐、OCR 和图像分类；LLM 初始化自 Qwen2，ViT 初始化自 DFN 但把固定位置改为 2D-RoPE。第二阶段解冻全模型，再加入约 800B 图像相关和纯文本 token，累计 1.4T。第三阶段冻结 ViT，用 ChatML 混合图像问答、文档解析、多图比较、视频流对话、函数调用、UI、机器人与导航。报告没有公开各子语料的完整样本占比，无法独立复算数据贡献。

## 实验

### 评价设计

实验覆盖通用 VQA、大学知识/数学、OCR/文档/图表、referring expression、短至一小时的视频，以及函数调用、手机 UI、ALFRED 机器人、卡牌游戏和 VLN。论文在同一表中同时放置公开权重和 API 模型，提示、版本、图像预算并不完全一致；跨模型差值适合作为当时快照，不宜视为长期固定排名。

### 旗舰模型结果

![Qwen2-VL 视觉与多语言 OCR 结果](/images/literature-notes/qwen2-vl/key-results.png)

*图 2｜表 2 汇总通用、文档、数学和综合视觉基准；表 3 为内部多语言 OCR。Qwen2-VL-72B 在 OCR/文档上突出，但 MMMU 仍低于 GPT-4o；内部 OCR 集缺少公开复现条件。来源：原论文表 2、表 3。*

| 指标 | Qwen2-VL-72B | GPT-4o（论文快照） | 解读 |
|---|---:|---:|---|
| MMMU | 64.5 | 69.1 | 综合知识/推理仍落后 |
| DocVQA | 96.5 | 92.8 | 高分辨率文档读取占优 |
| OCRBench | 877 | 736 | OCR 优势明显 |
| RealWorldQA | 77.8 | 75.4 | 真实场景问答略高 |
| MathVista | 70.5 | 63.8 | 论文协议下视觉数学更高 |

表 2 同时显示 2B→7B→72B 对数学、MMMU 的提升更显著，而 OCR 在小模型上已较强。作者据此把视觉感知瓶颈与语言推理瓶颈区分开：增加分辨率能帮助文字，但不会自动解决 MMMU。

### 动态分辨率消融

Qwen2-VL-7B 固定 64/576/1600/3136 个视觉 token 时，OCRBench 为 572/828/824/786；动态策略平均 1924 token，达到 866（表 7）。InfoVQA 固定 3136 略高于动态（77.27 vs. 75.89），而动态在 OCRBench 更好；没有一个固定预算统治所有任务。过度放大小图还会让 OCRBench 下降，说明“更多像素”可能造成分布外输入。

### M-RoPE 与视频

用较小 Qwen2-1.5B+ViT-L 消融时，M-RoPE 相对 1D-RoPE 在 PerceptionTest/NextQA/STAR 从 46.6/43.9/55.5 提升到 47.4/46.0/57.9；图像任务有升有降，例如 RealWorldQA 54.5→53.7、InfoVQA 50.8→50.3（表 8）。最大训练长度 16K token，但 Video-MME 中推到 80K 仍较稳定（图 5）；这是位置外推证据，不等于模型真正训练过同等长度的密集视频。

### Agent 实验

内部视觉函数调用的 Type Match/Exact Match 为 93.1/53.2，GPT-4o 快照为 90.2/50.0（表 5）。ALFRED valid-unseen 略高于专用 ThinkBot，手机 UI 和卡牌也有竞争力；R2R/REVERIE 则与 GPT-4o 接近且显著落后专用导航模型。论文将差距归因于多图生成的地图不完整，说明二维 grounding 尚未转化为可靠三维记忆。

## 主要发现

1. **动态视觉带宽强化文档与真实场景感知。** 72B 模型在 DocVQA、OCRBench、RealWorldQA 分别为 96.5、877、77.8；论文中的 GPT-4o 对照为 92.8、736、75.4（表 2）。
2. **分辨率不能替代综合推理。** MMMU 上 Qwen2-VL-72B 为 64.5，低于论文对照 GPT-4o 的 69.1（表 2）。作者也把这类差距归因于推理，而不是继续增加图像 token 即可解决。
3. **动态分辨率与 M-RoPE 是折中而非单调增益。** 消融中约 1924 个动态视觉 token 的 OCRBench 为 866，固定 3136 token 为 786，但后者在个别文档指标略高；M-RoPE 对视频提升更稳定，部分图像任务持平或轻微下降。
4. **通用 agent 能力尚不等于长期行动。** 函数调用 Type Match/Exact Match 为 93.1/53.2，高于论文对照 GPT-4o 的 90.2/50.0（表 5）；但 R2R、REVERIE 等导航任务仍落后专用模型。

## 结论

作者认为，动态分辨率、统一图像/视频编码与 M-RoPE 使 Qwen2-VL 能以一个模型覆盖从像素级文字到长视频、GUI 和机器人等任务，并体现模型与数据扩展的收益。

## 局限与适用边界

### 证据边界

- 技术报告未同行评审，部分数据、内部 OCR 集和去重流程不可审计。
- 动态 token 让高分辨率输入成本随像素增加；论文没有提供统一硬件与输入预算下的完整延迟/显存曲线。
- 不同消融的 token 数和任务权重并不完全等价，不能概括为“动态一定优于固定”。
- Agent 评价以函数调用、UI 操作和短任务为主，尚未证明长期闭环可靠性。
- 跨论文的 GPT-4o 对照依赖当时 API 快照和提示，不宜作为永久模型排名。
- 视频固定 2 FPS、最多 768 帧/约 16K 训练视觉 token，会漏掉短暂事件；长视频成绩应与采样策略一起解读。
- M-RoPE 在视频上总体增益清晰，但若没有保持训练数据与 token 预算完全一致，不能把所有 Qwen1→Qwen2 提升归因于位置编码。
- 视觉 agent 依赖历史图像不断加入 32K 上下文，没有显式状态估计或地图一致性；成功率不足以证明对环境变化和执行误差稳健。

## 我的思考

Qwen2-VL 的核心不是简单提高分辨率，而是让视觉计算随输入信息量变化。更成熟的系统还应让 token 预算随问题难度变化：读取小字时保留高分辨率，做全局分类时主动压缩，并用不确定性决定是否再次放大局部区域。
