## 核心结论

DeepSeek-V3 延续 [DeepSeek-V2](/posts/deepseek-v2/) 的 MLA 与 DeepSeekMoE，把模型扩到 **671B 总参数、37B 每 token 激活参数**，在 14.8T token 上预训练。新增三项方法分别处理 MoE、训练信号和数值效率：用动态专家 bias 做 batch-level 负载均衡，减少强辅助损失对专家分工的干扰；用 Multi-Token Prediction（MTP）让每个位置额外预测未来 token；用细粒度 FP8 量化训练大部分 GEMM，并通过 FP32 累积和高精度敏感算子控制误差。

“auxiliary-loss-free”容易被误读。V3 不再以主要的 batch-level 辅助损失拉平专家，而是调节只影响 top-k 选择的 bias；但它仍以 \(\alpha=10^{-4}\) 保留一个很小的 sequence-wise balance loss，避免单条序列极端不均衡。更准确的中文是“以无主辅助损失的 bias 路由为主”，不是“训练中不存在任何负载均衡损失”。

成本表可核验：预训练 2.664M、上下文扩展 119K、后训练 5K，共 **2.788M H800 GPU-hours**；按作者假设的 2 美元/H800-hour 为 5.576M 美元。论文明确排除架构、算法、数据的先前研究与消融，因此该数字是“官方最终训练运行成本”，不是从项目立项到模型发布的总研发成本。

## 研究背景

V2 已证明“低 KV cache + 稀疏 FFN”可以让大容量模型更经济，但扩到数百 B 参数还会遇到三个瓶颈。第一，为负载平衡增加较强 auxiliary loss 会强迫不同领域的 token 使用相似专家，可能妨碍专业化；第二，next-token prediction 每位置只有一个监督目标，数据效率与未来规划信号有限；第三，BF16 大规模训练的计算/通信成本仍高，而直接用 FP8 会受到动态范围、累积精度和异常值影响。

V3 将这些算法问题和集群执行同时设计：64-way expert parallel 使跨节点 all-to-all 成为主要通信，DualPipe 用双向流水与计算—通信重叠隐藏它；细粒度量化适应激活/权重动态范围；node-limited routing 限制 token 最多跨 4 节点。论文的“经济”由这个整体产生，不能只看 MoE 或 FP8 标签。

## 研究问题

1. 如何平衡 256 个路由专家，而不让强辅助损失削弱专家专业化和主任务性能？
2. MTP 是否能以更密集的未来 token 监督改善主模型，并兼作 speculative decoding 草稿器？
3. FP8 能否在 671B MoE 上稳定训练，同时把相对损失误差控制在训练随机性量级？
4. 如何在 2,048 张 H800 上隐藏跨节点 expert all-to-all，并避免 tensor parallel 的额外内存/通信？
5. 14.8T-token 基座和 R1 蒸馏后的 Chat 模型，在哪些数学、代码、知识与对话任务上有效，哪些仍弱？

## 方法与数据

![DeepSeek-V3 总体架构](/images/literature-notes/deepseek-v3/architecture.png)

*图 1｜V3 继承 MLA 与细粒度 DeepSeekMoE；图中蓝框 latent 与解耦 RoPE key 是生成时缓存项，MoE 由共享专家与 top-k 路由专家组成。来源：原论文 Figure 2，PDF 第 7 页。[原论文 PDF](https://arxiv.org/pdf/2412.19437#page=7)*

### 1. 主干：MLA 与 DeepSeekMoE

MLA 先联合压缩 K/V：

$$
c_t^{KV}=W^{DKV}h_t,\quad
k_t^C=W^{UK}c_t^{KV},\quad
v_t^C=W^{UV}c_t^{KV},
$$

并把带 RoPE 的位置 key \(k_t^R\) 与内容 key 分开，只缓存 \(c_t^{KV}\) 和 \(k_t^R\)。这继承 V2 的低 KV cache 接口。

V3 有 61 层、hidden size 7,168；MLA 为 128 heads、每 head 128 维，KV/query 压缩维分别 512/1,536，RoPE 通道 64 维。除前 3 个 FFN 外均替换为 MoE；每个 MoE 层有 **1 个共享专家 + 256 个路由专家**，每 token 选 8 个，单专家 intermediate size 2,048。每 token 最多发送到 4 个节点，不做 token dropping。最终为 671B total / 37B active。[原论文 §2.1、§4.2](https://arxiv.org/pdf/2412.19437#page=7)

与 V2 softmax gate 不同，V3 用 sigmoid affinity 并在被选专家间归一化：

$$
s_{i,t}=\sigma(u_t^\top e_i),\qquad
g_{i,t}=\frac{s_{i,t}\mathbf 1[i\in\mathcal T_t]}
{\sum_j s_{j,t}\mathbf 1[j\in\mathcal T_t]}.
$$

### 2. Auxiliary-loss-free 负载均衡

为每个路由专家维护 bias \(b_i\)，选择集合由 \(s_{i,t}+b_i\) 的 top-k 决定，但真正乘专家输出的 gate 仍来自原始 \(s_{i,t}\)：

$$
\mathcal T_t=\operatorname{TopK}_i(s_{i,t}+b_i,K_r).
$$

每个训练 step 结束，若专家过载则 \(b_i\leftarrow b_i-\gamma\)，欠载则 \(b_i\leftarrow b_i+\gamma\)。这相当于一个不反向污染语言建模损失的负反馈控制器：bias 改“谁被选”，不改“被选专家贡献多大”。前 14.3T token 的 \(\gamma=0.001\)，最后 500B token 置 0。

但 V3 仍保留权重极小的 sequence-wise balance loss：

$$
\mathcal L_{bal}=\alpha\sum_i f_iP_i,\qquad \alpha=10^{-4},
$$

用于防止单条序列内极端不平衡。论文消融时会在对照模型中移除全部 auxiliary loss 并使用 bias 方法；最终 671B 配置则有上述微小补充项。[原论文 §2.1.2](https://arxiv.org/pdf/2412.19437#page=8)

### 3. Multi-Token Prediction（MTP）

![DeepSeek-V3 的 MTP](/images/literature-notes/deepseek-v3/mtp.png)

*图 2｜MTP 沿深度顺序预测更远 token。每个模块接收上一级 hidden 和相应未来 token 的 ground-truth embedding，保留完整因果链；embedding 与 output head 和主模型共享。V3 实际设置 \(D=1\)，即除 next token 外再预测一个 token。来源：原论文 Figure 3，PDF 第 10 页。[原论文 PDF](https://arxiv.org/pdf/2412.19437#page=10)*

第 \(k\) 个 MTP 模块先融合前一深度表征和第 \(i+k\) 个真实 token embedding：

$$
h_i^{\prime k}=M_k[\operatorname{RMSNorm}(h_i^{k-1});
\operatorname{RMSNorm}(\operatorname{Emb}(t_{i+k}))],
$$

再经独立 Transformer block 得到 \(h_i^k\)，由共享输出头预测更远 token。总辅助目标为各深度交叉熵平均：

$$
\mathcal L_{MTP}=\frac{\lambda}{D}\sum_{k=1}^{D}\mathcal L_{MTP}^k.
$$

V3 取 \(D=1\)：每位置额外预测第二个 token；\(\lambda\) 前 10T token 为 0.3，后 4.8T 为 0.1。部署可丢弃 MTP 模块，不增加主模型常规推理成本；也可把它用于 speculative decoding。报告称额外 token 接受率 85%–90%，系统实现约 1.8× TPS，但没有跨硬件、batch 和长度的完整延迟曲线。[原论文 §2.2、§5.4.3](https://arxiv.org/pdf/2412.19437#page=10)

### 4. FP8 混合精度

前向 GEMM、activation-gradient GEMM 和 weight-gradient GEMM 的主要输入以 FP8 计算，部分输出保留 BF16/FP32；embedding、归一化、attention、MoE gating 等敏感算子使用更高精度。为适应异常值，激活按 **1×128 tile**、权重按 **128×128 block** 计算缩放因子，并定期在 FP32 中累积 partial sums。MoE dispatch activation 也缓存/传输为 FP8，低精度 optimizer states 用 BF16。

数值验证在两个接近 V2-Lite/V2 规模的模型上训练约 1T token，与 BF16 的相对 loss error 始终低于 0.25%。这说明配方在代表性规模上稳定；论文并没有训练一个完整 671B BF16 twin，因此不能把最终模型质量与 BF16 做全尺寸等价证明。[原论文 §3.3、Appendix B.1](https://arxiv.org/pdf/2412.19437#page=15)

### 5. 集群与 DualPipe

训练集群为 **2,048 张 NVIDIA H800**，每节点 8 GPU；节点内 NVLink/NVSwitch，节点间 InfiniBand。并行组合为 16-way PP、64-way EP（跨 8 节点）和 ZeRO-1 DP，不使用 TP。DualPipe 从流水线两端同时送入 micro-batch，把 attention、MoE dispatch、MLP、combine 以及 backward-input/backward-weight 重排，力求用计算遮蔽 all-to-all 和 PP 通信。[原论文 §3.1–3.2](https://arxiv.org/pdf/2412.19437#page=11)

这是针对 H800 拓扑和自研 kernels 的系统设计。官方仓库未开放生产 HAI-LLM/DualPipe 实现；其他网络、专家布局或序列分布是否得到同样 MFU，需要重新测量。

### 6. 数据、优化与后训练

- **预训练数据**：14.8T token；相对 V2 增加数学、代码和多语言，改进去冗余；document packing 不做跨样本 attention mask；以 0.1 概率加入 PSM 形式 FIM。
- **tokenizer**：128K BBPE；为改善多语言压缩加入标点+换行组合 token，并通过随机拆分缓解多行 prompt 的 token-boundary bias。
- **优化**：AdamW（0.9/0.95，weight decay 0.1），4K 序列；2K warm-up 到 \(2.2\times10^{-4}\)，10T 前恒定，之后 4.3T cosine 降到 \(2.2\times10^{-5}\)，最后 500B 再阶梯到 \(7.3\times10^{-6}\)；batch 在前 469B token 从 3,072 增到 15,360。
- **上下文**：YaRN 两阶段，各 1,000 step，把 4K 扩到 32K、再到 128K；batch 分别 1,920/480。
- **SFT/RL**：约 1.5M SFT 实例，推理数据由内部 DeepSeek-R1 系列生成，非推理由 V2.5 与人工构造；2 epochs。RL 使用 rule/model-based rewards 与 GRPO，在准确性和生成长度之间做平衡。

后训练吸收 R1 推理能力意味着 V3 Chat 的推理结果不能只归因于 V3 基座架构；它还包含教师生成数据和 RL 配方。

## 实验

### 1. 官方训练计算账单

| 阶段 | H800 GPU-hours | 按 $2/GPU-hour 换算 |
|---|---:|---:|
| 14.8T 预训练 | 2.664M | $5.328M |
| 上下文扩展 | 119K | $0.238M |
| 后训练 | 5K | $0.010M |
| **合计** | **2.788M** | **$5.576M** |

论文还给出每 1T token 约 180K H800-hours；2,048 GPU 上约 3.7 天。表格明确不含先前架构、算法、数据研究和消融，也没有数据采购、人员、集群折旧、电力与服务部署成本。[原论文 Table 1](https://arxiv.org/pdf/2412.19437#page=4)

### 2. MTP 与路由消融

MTP 在 15.7B/1.33T-token 与 228.7B/540B-token 两个规模上做受控对照。多数任务提高，例如大型模型 HumanEval 44.5→53.7，小模型 HumanEval 20.7→26.8；但大型 MMLU 67.5→66.6、小型 NaturalQuestions 22.7→22.3。结论应是“多数 benchmark 有益”，不是“每项都提升”。[原论文 Table 4](https://arxiv.org/pdf/2412.19437#page=25)

辅助损失路由对照同样有例外：大型 MMLU 68.3→67.2、小型 MBPP 36.6→35.8，但大型 HumanEval 40.2→46.3、GSM8K 70.7→74.5、MATH 37.2→39.6，Pile BPB 0.656→0.652。实验支持 batch-level balancing 减少部分能力干扰，尚不能证明它是 671B 最终分数的唯一原因。[原论文 Table 5](https://arxiv.org/pdf/2412.19437#page=26)

### 3. Base 模型

Table 3 中，V3 Base 的 MMLU 87.1、HumanEval 65.2、MATH 61.6，高于表内 Qwen2.5-72B 的 85.0/53.0/54.4 和 Llama-3.1-405B 的 84.4/54.9/49.0；但 Pile BPB 0.548 略差于 Llama 的 0.542，RACE-Middle 67.1 也低于 Qwen 68.1 和 Llama 74.2。V3 的优势集中在代码、数学和多项知识任务，并非全表统治。[原论文 Table 3](https://arxiv.org/pdf/2412.19437#page=24)

### 4. Chat 与闭源比较

V3 Chat 在作者表中 MMLU 88.5、GPQA-Diamond 59.1、AIME 2024 39.2；SimpleQA 24.9 低于 GPT-4o 38.2 和 Claude-3.5-Sonnet 28.4，SWE-bench Verified 42.0 低于 Claude 的 50.8。对 GPT-4o/Claude 的数字来自特定 API 快照和各自提示协议，且部分开放式任务依赖模型裁判；“comparable”只能理解为所列基准的混合表现，而非总体能力等价。[原论文 Table 6](https://arxiv.org/pdf/2412.19437#page=30)

### 5. 128K 与部署

128K 主要由 NIAH 检索测试支持；它不足以证明 128K 多文档推理。论文部署章节还表明推荐单元很大：prefill 最小 4 节点/32 GPU，decode 描述的最小单元达 40 节点/320 GPU。高吞吐与低单 token 成本可能成立，但不等于小团队能以单机低延迟运行 671B 模型。

## 主要发现

1. **V3 是 co-design 结果。** MLA/MoE、bias 路由、MTP、FP8、DualPipe 和网络内核共同决定效率；拆掉系统条件后不能保证同一成本。
2. **auxiliary-loss-free 是主机制描述，不是字面零损失。** batch-level 以 bias 控制，仍保留 \(10^{-4}\) 的 sequence loss。
3. **MTP 同时是训练目标和推理接口。** 常规推理可丢弃模块，speculative decoding 可复用它；消融显示多数任务受益，但有回退项。
4. **FP8 证据有尺度边界。** 约 1T-token 的较小模型对照控制了 loss error，最终 671B 没有 BF16 twin。
5. **2.788M 是有定义的训练账单。** 它比模糊的“数百万美元开发成本”更可信，也恰恰因为排除项明确而不能外推成总成本。

## 局限与适用边界

### 作者明确报告的局限

- 高效推理所需部署单元仍很大，对小团队构成负担；
- 端到端生成速度虽超过 V2 两倍，仍有提升空间；
- 未来需要更高效架构、更长上下文、更丰富数据/信号和更全面评价，避免固定 benchmark 导向。[原论文 §6](https://arxiv.org/pdf/2412.19437#page=35)

### 额外证据边界

- **成本不是总研发成本**：明确排除研究与消融，美元值依赖 2 美元/H800-hour 假设，也不含人力、数据与服务。
- **FP8 缺少全尺寸 BF16 对照**：小规模数值稳定不能严格证明 671B 与 BF16 等价。
- **组件归因受限**：最终模型同时改变数据、容量、MTP、路由、精度和后训练；小模型消融不能完全外推。
- **训练数据不可审计**：14.8T 来源、授权、去污染日志与 R1 蒸馏数据未公开。
- **软件复现受限**：官方仓库没有 HAI-LLM、DualPipe 完整训练栈和训练数据。
- **128K 证据单薄**：NIAH 强调定位，不代表综合理解、位置鲁棒性或稳定有效上下文。
- **榜单与裁判偏差**：闭源 API 会更新，prompt/harness 不完全统一，开放问答还受 LLM judge 与长度偏好影响。

## 路线关系

[DeepSeek LLM](/posts/deepseek-llm/) 先建立密集模型和缩放基线；[DeepSeek-V2](/posts/deepseek-v2/) 引入 MLA、DeepSeekMoE 和 GRPO；V3 沿用它们并解决更大规模下的负载、训练信号和数值/通信问题。随后 [DeepSeek-R1](/posts/deepseek-r1/) 直接以 DeepSeek-V3-Base 为策略初始化，用可验证奖励和大规模 GRPO 获得长推理，再把该能力蒸馏回 V3 Chat 的后训练数据。V3 因而既是架构路线的峰值，也是 R1 后训练路线的底座与受益者。

## 我的思考

V3 最有方法论价值的地方，是把术语拆成可测量接口：MoE 看 load variance 和 active FLOPs，FP8 看 loss error，MTP看受控 benchmark 与 acceptance rate，系统看 GPU-hours。反过来，最容易误读的也是把这些接口压成“低成本大模型”口号。研究复现时应优先对齐硬件拓扑、数值精度、路由容量和成本边界，再讨论美元数。

一个更强的后续证据包应包含：全尺寸或至少更接近全尺寸的 BF16/FP8 A/B；同数据的多种路由方法与专家专门化指标；不同集群拓扑上的吞吐/延迟曲线；以及研发、训练、后训练和部署分别计账。这样才能判断技术是“在特定集群上做得很好”，还是“跨环境可迁移”。

## 结论

DeepSeek-V3 不是依靠单项魔法把 671B 模型降到 37B 计算，而是通过稀疏架构、状态压缩、负载控制、密集训练信号、FP8 和通信重叠共同兑现效率。论文给出的成本和实验足够具体，贡献也经多尺度消融支持；但开放训练栈、数据、全尺寸精度对照和总研发成本仍缺失。准确保留这些边界，比重复“5.576M 美元训练 GPT-4 级模型”的传播性叙事更重要。
