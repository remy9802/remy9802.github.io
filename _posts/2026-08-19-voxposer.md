## 核心结论

VoxPoser 的核心接口是**可组合三维 value map**。LLM 先把长任务分解为子任务，再生成 Python 调用感知接口；VLM 找出相关对象，程序在 $100\times100\times100$ 体素网格上建立目标吸引、障碍排斥、末端旋转、速度和夹爪状态等地图。运动规划器把这些地图当作代价函数和控制参数，生成并闭环执行轨迹。

在五项真实机器人任务、每项 10 次试验中，VoxPoser 静态场景成功率为 **88%**，人为扰动下为 **70%**；基于 LLM 选择预定义 primitives 的对照分别为 **24% 和 0%**。RLBench 的 13 项任务、2,766 条指令中，它在最难的 unseen-instruction/unseen-attribute 组合任务达到 **76.7%**，高于 primitive baseline 的 25%。这些结果支持：显式空间地图能比离散技能调用更好地表达连续几何目标，并能在执行时根据新观测重建地图。

边界在于，VoxPoser 并没有学到通用物理世界模型。大多数任务假设环境静态；涉及接触时，论文另外使用简单点云平移先验和仿真探索学习局部动力学。真实机器人试验小、没有置信区间，主要失败来自外部视觉模块；官方代码也只覆盖 RLBench demo。

## 研究背景

LLM 可以把任务写成动作序列或程序，却常缺少连续三维 grounding。诸如“把花瓶放在左边但离机器人和笔记本都远一点”并不是一个离散技能名：它定义了工作空间中每个候选位置的偏好与禁区。传统运动规划器擅长优化这种目标，却需要工程师手写代价函数；端到端策略能从示范学习代价，但很难在训练外组合新语言约束。

VoxPoser 的折中是：让 LLM/VLM 负责**写出空间代价**，让运动规划器负责**满足几何约束**。体素地图具有统一接口，来自语言的多个偏好可以相加，感知更新后也可以重新计算。这比 Code as Policies 直接生成完整控制代码更结构化，又比 SayCan 的离散技能选择更能表达连续位置、避障和朝向。

## 研究问题

1. LLM 能否根据语言和检测到的实体，程序化生成可解释的三维 affordance 与 constraint maps？
2. 多张 value map 能否组合成运动规划目标，同时控制末端朝向、速度和夹爪？
3. 重新观测并重建地图能否抵抗真实执行过程中的外部扰动？
4. 这种空间表示能否泛化到未见指令、属性与任务组合？
5. 对需要接触动力学的任务，语言先验与少量交互学习能否共同提高样本效率？

## 方法与数据

![VoxPoser 三维价值地图组合与运动规划](/images/literature-notes/voxposer/method-overview.png)

*图 1｜VLM 定位语言涉及的对象，LLM 生成代码构造 affordance 与 constraint maps；规划器在三维体素空间优化轨迹。图中的锁表示感知模型和语言模型不再训练。来源：原论文 Figure 2，PDF 物理页 4。[原文 PDF](https://proceedings.mlr.press/v229/huang23b/huang23b.pdf#page=4)*

### 1. 从语言子任务到优化问题

LLM planner 先把高层指令分成子任务 $\ell_i$。对第 $i$ 个子任务，目标写为

$$
\min_{\tau_i^r}
\left\{
F_{\mathrm{task}}(\mathcal T_i,\ell_i)
+F_{\mathrm{control}}(\tau_i^r)
\right\}
\quad
\text{s.t. } C(\mathcal T_i),
$$

其中 $\tau_i^r$ 是机器人轨迹，$\mathcal T_i$ 是与任务相关实体的轨迹，$F_{\mathrm{task}}$ 表达语言目标，$F_{\mathrm{control}}$ 表达路径平滑等控制代价，$C$ 是约束。

若实体 $e$ 在轨迹点 $p_j^e$ 上移动，体素 value map $V$ 将任务目标实现为

$$
F_{\mathrm{task}}=-\sum_j V(p_j^e).
$$

高值体素吸引实体，低值或负值区域排斥它。于是“靠近花”“避开花瓶”“把把手朝上”等语言条件不必直接变成动作，而先变成可检查的空间场。

### 2. LLM 生成的是地图程序，不是体素值文本

作者使用 GPT-4，并为每个 language-model program（LMP）提供约 5–20 个 few-shot 示例。composer LMP 生成 Python，调用：

- VLM 目标检测与分割接口；
- 物体中心、点云、边界和机器人状态；
- NumPy 距离、法向量、坐标变换和插值；
- map constructor，将连续值落到 $100\times100\times100\times k$ 网格。

地图分为五类：

1. **affordance map**：末端执行器或被操作实体应到达哪里；
2. **avoidance map**：碰撞与语言禁区；
3. **rotation map**：每个位置对应的期望末端朝向；
4. **velocity map**：不同区域的速度偏好；
5. **gripper map**：开合状态或触发时机。

代码可复用对象检测结果并组合多张图，解释性强于黑箱动作头；但地图质量仍取决于提示词、API 契约和生成代码正确性。

### 3. 感知栈

真实系统用 OWL-ViT 根据开放词汇得到 2D 框，SAM 提取 mask，XMEM 跨帧追踪，再将双 RGB-D 相机的深度投影到三维点云。对每个对象估计位置、范围和表面几何，供程序构图。

这条 pipeline 不是统一训练的 VLM：检测、分割、追踪和深度误差会级联。作者的失败分析也指出，大部分真实失败来自检测器对物体姿态、细粒度部件或新视角敏感。

### 4. 运动规划与闭环

规划器使用贪心搜索，在候选节点上计算归一化 affordance 与 avoidance maps 的加权和，论文设置二者权重为 2:1，并加入控制代价。系统只执行第一个 waypoint，然后根据新 RGB-D 观测更新点云与地图，以约 5 Hz 重规划；末端轨迹由 operational-space controller 执行。

因此 VoxPoser 的反馈闭环位于“感知—重建地图—重规划”层，而不是让 LLM 每个控制周期重新生成文本。静态场景通常只需首次调用 LLM/VLM，后续快速更新地图。

### 5. 接触动力学扩展

一般操作假设环境近似静态。对推/开门等接触任务，作者允许 LLM 给出一个粗糙动力学先验，例如把物体点云按末端位移做平面平移；再在仿真中以 model-based RL 的方式收集交互，学习残差动力学并优化动作。

这不是通用 world model：它只面向特定对象/接触原语，动力学实验也只在模拟 Door、Window、Fridge 上进行。

### 6. 训练与推理边界

| 模块 | 训练 | 推理 |
|---|---|---|
| GPT-4 / VLM | 不由 VoxPoser 更新 | few-shot 生成任务分解与构图代码，检测相关对象 |
| Value maps | 无数据训练 | 由生成程序和当前三维观测即时计算 |
| 运动规划器 | 无学习 | 在组合地图上搜索并闭环重规划 |
| 动力学扩展 | 接触任务中可用仿真交互学习 | 用先验加学习模型预测接触效果 |

## 实验

### 1. 真实机器人：5 项任务 × 10 次

平台为 Franka Emika Panda，测试 Move & Avoid、Set Up Table、Close Drawer、Open Bottle 和 Sweep Trash。每项分别测试静态环境与执行中人为移动物体的 disturbance 条件。

![VoxPoser 真实机器人与 RLBench 主结果](/images/literature-notes/voxposer/main-results.png)

*图 2｜左表是五项实机任务每项 10 次；右表是 RLBench 13 项任务。VoxPoser 的优势在扰动和未见属性组合上最明显。来源：原论文 Tables 1–2，PDF 物理页 7。[原文 PDF](https://proceedings.mlr.press/v229/huang23b/huang23b.pdf#page=7)*

| 方法 | 静态 | 扰动 |
|---|---:|---:|
| LLM + predefined primitives | 24%（12/50） | 0%（0/50） |
| VoxPoser | **88%（44/50）** | **70%（35/50）** |

逐任务上，VoxPoser 静态/扰动成功次数分别为：Move & Avoid 9/8、Set Up Table 9/7、Close Drawer 10/7、Open Bottle 7/5、Sweep Trash 9/8。每格只有 10 次，因而一个 trial 就对应 10 个百分点；论文未报告不同随机种子或置信区间。

primitive baseline 的 0% 扰动结果支持离散开环技能不适合在线修正空间目标，但不代表所有技能库方法都会失败：基线的原语设计、是否允许反馈和规划能力明显弱于完整 VoxPoser。

### 2. RLBench：组合泛化

13 个任务分为 object interaction 与 composition 两类，共 2,766 条独特自然语言指令，每任务 20 个 episodes。`SI/UI` 表示 seen/unseen instructions，`SA/UA` 表示 seen/unseen attributes。

| 分布 | 类别 | U-Net | LLM primitives | VoxPoser |
|---|---|---:|---:|---:|
| SI / SA | Object interaction | 21.0% | 41.0% | **64.0%** |
| SI / SA | Composition | 53.8% | 43.8% | **77.5%** |
| SI / UA | Object interaction | 3.0% | 46.0% | **60.0%** |
| SI / UA | Composition | 3.8% | 25.0% | **58.8%** |
| UI / UA | Object interaction | 0% | 17.5% | **65.0%** |
| UI / UA | Composition | 0% | 25.0% | **76.7%** |

显式程序与地图在未见属性上不需要重新训练 U-Net，因而组合泛化优势显著。但官方开源 demo 使用 RLBench 提供的 ground-truth masks，这比论文实机感知设置更容易，复现者不能把两者视为相同 perception condition。

### 3. 动力学学习

三个仿真接触任务各运行 3 个随机种子：

| 配置 | Door | Window | Fridge |
|---|---:|---:|---:|
| Zero-shot language prior | 6.7% ± 4.4 | 3.3% ± 3.3 | 18.3% ± 3.3 |
| 无语言先验学习 | 58.3% ± 4.4 | 36.7% ± 1.7 | 70.0% ± 2.9 |
| 语言先验 + 学习 | **88.3% ± 1.7** | **80.0% ± 2.9** | **91.7% ± 4.4** |

带先验达到阈值的时间分别约 142.3、137.0 和 71.0 秒；无先验一栏标为 `TLE (>12 h)`。值得注意的是，无先验仍报告非零最终成功率却同时标记超过 12 小时，表格没有充分解释成功率取自何时或何个 budget，复现时需要作者代码或日志澄清。

## 主要发现

1. **空间 value map 是有效中间表示**：它把语言约束、三维观测与成熟运动规划连接起来。
2. **闭环重规划显著增强扰动鲁棒性**：实机从 baseline 的 0% 提升到 70%，但比较中同时改变了表示和反馈机制。
3. **组合泛化强于训练式 U-Net**：未见指令与属性下，程序化构图不依赖任务级再训练。
4. **语言先验能加速局部动力学学习**：三个仿真接触任务均比无先验更快、更高，但不是通用世界模型证据。
5. **感知仍是实机瓶颈**：外部 detector/segmenter/tracker 的错误直接污染地图。

## 结论

VoxPoser 展示了一种比“LLM 输出动作”更稳健的分工：语言模型定义目标，视觉模型提供实体，体素地图把两者 grounding 到三维空间，运动规划器负责求解连续轨迹。该结构让生成结果可视化、可组合，也能在状态变化后快速重规划。

它最适合目标和约束能写成局部空间场、机器人末端轨迹足以完成任务的操作问题。需要全身碰撞、快速动态交互、长期记忆或复杂接触动力学时，原框架并不完整。

## 局限与适用边界

### 作者明确承认的局限

- 性能受外部感知模型限制，整体物体与细粒度部件检测、姿态变化和遮挡会失败。
- 大多数任务使用静态世界假设；论文没有统一、通用的可学习动力学模型。
- 只规划末端执行器轨迹，没有把全机械臂或全身几何统一纳入语言生成的 value map。
- 每个 LMP 依赖人工编写的 5–20 个 prompt examples，提示工程仍是主要成本。

### 额外证据审计

- “zero-shot”指不训练新任务策略，不代表没有手工 API、提示词、感知器、控制器和运动规划工程。
- 真实试验每任务仅 10 次，没有置信区间、盲评、随机化明细或端到端延迟报告。
- primitive baseline 没有同等强的在线空间反馈，不能把全部差异只归因于 value-map 表示。
- 约 5 Hz 的重规划没有安全 deadline、最坏时延或高速动态物体测试。
- 末端避障不等于全机械臂/机器人碰撞安全，地图也不保证动力学可行性。
- LLM 生成 Python 同样存在错误调用与执行安全风险，论文未提供形式验证或严格沙箱。
- 官方仓库只覆盖 RLBench demo，并依赖 ground-truth masks；实机感知、标定和控制不可直接复现。
- 动力学实验只在模拟的三个接触对象上，不能支持“通用物理推理”结论。

## 我的思考

VoxPoser 的重要启发是：LLM 最有价值的输出未必是动作或代码，而可能是一个**优化器可消费的目标表示**。相比自由代码，value map 限制了输出空间，也让人能直接查看“机器人为什么想去这里、避开那里”。

下一步最值得做的是把它从经验性体素打分升级为带不确定性的约束优化：感知置信度低的区域应扩大安全边界；不同语言约束应有可追踪优先级；全臂碰撞、关节极限与动力学可行性应进入同一求解器。若再接入学习世界模型，应让模型预测“动作如何改变地图”，而不是只给静态场打分。

在五篇路线对比中，VoxPoser代表“**空间 value map + 传统规划器**”：比 SayCan 的离散技能更连续，比 CaP 的任意程序更结构化，比 Inner Monologue 的文本反馈保留更多几何信息。
